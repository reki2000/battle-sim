# 提案: 地形生成 v2 — 参照点の自動増殖と侵食による起伏

**状態**: 提案（未承認）。承認されたら `docs/spec/03-terrain.md` と
`docs/spec/08-rendering.md` へ取り込み、ロードマップに M10 として載せる。

**要求**

1. 起伏がリアルであること。**参照点の間を単になだらかに繋ぐだけにしない**
2. そのために、少数の参照点から**追加の参照点を多数、自動生成**する
3. **侵食でできた崖**と、**なだらかな丘**が出ること
4. 隣接セルとの高低差が大きい崖もあり得る
5. 段差は高低差に応じた**複数枚のポリゴン**で繋ぎ、適切なテクスチャを選ぶ
6. 樹木・岩は**ポリゴン**で描画する
7. シード付き乱数から一意に生成される
8. 事前に数点の標高と全体の属性を指定し、残りは自動生成する

**グリッドは 2 m のまま**（現行どおり）。解像度を上げず、設計を単純に保つ。

## 1. 現状とのギャップ

| 要求 | 現状 | 差分 |
|---|---|---|
| リアルな起伏 | fBm + ridged ノイズを 8 m 間隔でサンプルしてバイリニア補間（`base_elevation`）。侵食は熱浸食のみ 6 反復 | **水系が地形を刻んでいない**。谷・尾根・段丘といった「水が作った形」が無く、ノイズの塊のまま |
| 参照点から自動生成 | `shaping::Stamp::HeightRamp` のみ。軸全体に効くランプ 1 本 | 「この地点は +3.2 m」が書けない。参照点という概念自体が無い |
| 侵食由来の崖 | `outcrop_bump_cm` が**ノイズの閾値超えを直接段差として足している**。`thermal_erosion` は「差が 250 cm 以上のペアを対象外」という規則で崖を守っている | 崖が地形の履歴と無関係な場所に出る。侵食から崖を守る規則も、本来なら岩の硬さが決めるべきものを閾値で代用している |
| なだらかな丘 | 熱浸食 6 反復のみ | 実際の丘の形（尾根が凸、谷頭が凹）を作る斜面拡散が無い |
| 段差をポリゴンで繋ぐ | **無い**。地形はマップ全体で 1 枚のクアッド（`terrain-gl.ts` の 4 頂点 `TRIANGLE_STRIP`）。頂点の高さ変位ゼロ、崖は `shade *= 0.55` で暗く塗るだけ | メッシュ化が必要 |
| 樹木・岩 | **無い** | 散布物のデータもジオメトリも無い |
| シード決定論 | **達成済み**（整数演算のみ、`Terrain::hash()` で検証） | v2 でも壊さない |

補足: 現在の描画は地形と兵士が**別の WebGL コンテキスト**（`terrainCanvas` /
`soldierCanvas`）で、地形は深度 0 の平面。崖と樹木を立てるならこの分離は先に畳む（7.4 節）。

## 2. 骨子

起伏のリアルさは、**「補間」ではなく「地形の履歴を作る」**ことで出す。順番はこうなる。

```
 少数の参照点（人が指定）
   ↓  ① 参照点の増殖: 制約付き中点変位  → 数万点の参照点が自動で生える（フラクタルな下地）
   ↓  ② 岩の硬さ場: 岩体ノイズ × 傾いた地層
   ↓  ③ 地形進化: 水系ルーティング → 河川下刻 → 斜面拡散 → 熱浸食（安息角は硬さ依存）
   │       を数十反復。人が指定した参照点は毎反復で再投影される
   ↓  ④ 2 m へ拡大（崖を潰さない補間）+ 微地形 + 崖錐
   ↓  ⑤ 水系確定・属性分類・崖グリッド・散布物
```

決めたことは 4 つ。

- **D1. 単一 2 m グリッド。** 層分けはしない。会戦シナリオの実寸 1,200 m なら 600² = 36 万セルで、
  重い処理も直接回せる。
- **D2. 参照点は増やしてから繋ぐ。** 数点を滑らかに補間すると「粘土をなでた面」にしかならない。
  階層的中点変位で参照点そのものを増やし、自己相似な下地を作る（3 章）。
- **D3. 崖は侵食の結果として出す。** ノイズで段差を足すのをやめ、**岩の硬さ場**を導入する。
  硬い岩は急な壁で立ち、軟らかい所は削れて崖錐で埋まる（4 章）。
- **D4. 描画は実ポリゴンメッシュ。** 固定ダイメトリックのカメラは維持したまま、地形だけ
  本物のジオメトリ + 正射影 + 実深度にする（7 章）。

## 3. 参照点の増殖（要求 1・2・8）

### 3.1 制約付き中点変位

粗格子（`2^k + 1` 四方、セル幅 4〜10 m に収まる `k` を選ぶ）で**ダイヤモンド・スクエア法**を
走らせる。人が指定した参照点は「固定点」として動かさず、それ以外を階層的に埋める。

```rust
/// 制約付き中点変位。`fixed` の点は動かさない。`dim = 2^k + 1`。
fn midpoint_displace(h: &mut [i32], fixed: &[bool], conf: &[u16],
                     dim: usize, seed: u64, hurst_pm: i32, amp0_cm: i32) {
    let mut step = dim - 1;
    let mut amp = amp0_cm;
    let mut level = 0u64;
    while step > 1 {
        let half = step / 2;
        // ダイヤモンド: 正方形の中心を 4 隅の平均 + 変位で埋める
        for y in (half..dim).step_by(step) {
            for x in (half..dim).step_by(step) {
                let avg = (at(h, x - half, y - half) + at(h, x + half, y - half)
                         + at(h, x - half, y + half) + at(h, x + half, y + half)) / 4;
                put(h, fixed, conf, x, y, avg + jitter(seed, level, x, y, amp));
            }
        }
        // スクエア: 辺の中点を 3〜4 近傍の平均 + 変位で埋める（省略）
        amp = amp * hurst_pm / 1000;   // 段が細かいほど振幅を落とす
        step = half;
        level += 1;
    }
}

/// 変位量は座標ハッシュから引く（逐次 RNG を使わない）。
fn jitter(seed: u64, level: u64, x: usize, y: usize, amp: i32) -> i32 {
    let h = splitmix64(seed ^ level.wrapping_mul(K0)
                            ^ (x as u64).wrapping_mul(K1)
                            ^ (y as u64).wrapping_mul(K2));
    ((h >> 40) as i32 % (2 * amp + 1)) - amp
}

/// 固定点は書き換えない。固定点の近くほど変位を弱める。
fn put(h: &mut [i32], fixed: &[bool], conf: &[u16], x: usize, y: usize, v: i32) { /* ... */ }
```

**なぜこれか。**

- 参照点が 3 点しかなくても、1 回の走査で粗格子の**全点（数万点）が参照点になる**。
  要求 2 そのもの。
- `hurst_pm`（ハースト指数、1000 分率）1 つで「なだらかな丘（800〜900）」と
  「ごつごつした山地（500〜600）」を切り替えられる。要求 3 の「なだらかな丘」は
  ここと斜面拡散（4.3 節）の合わせ技で出る。
- 固定点は値をそのまま保つので、人の指定が壊れない。
- 整数のまま書ける。座標ハッシュなので逐次 RNG が要らず、部分生成しても同じ結果になる。

**既知の弱点**: ダイヤモンド・スクエアは軸方向に折り目（クリース）が出やすい。
各段の後に緩和を 1 スイープ挟むと消える（3.3 節と同じ処理を流用）。

### 3.2 参照点の種類

| 種類 | 与えるもの | 用途 |
|---|---|---|
| `height_point` | 座標 + 標高 (+ 影響半径 + 重み) | 「英軍が立つ微高地の頂点は +3.2 m」 |
| `contour` | ポリライン + 標高 | 地形図から写した等高線。実在地形の再現はこれが主役 |
| `region` | ポリゴン + 地表 + 縁のノイズ量 + 優先度 | 森・耕地・砂地・湿地の「全体の属性」 |
| `river` | ポリライン + 川幅 + 水深 | 河道を強制する（5.2 節） |
| `biome` | プリセット名 | 領域指定の無い場所を埋める規則の束（6.2 節） |

線・面の制約は粗格子へラスタライズして固定点にするだけで、点と同じ扱いになる。

### 3.3 制約の再投影と信頼度

固定点は最近格子点へスナップされるので数 m のズレが出る。また侵食（4 章）は固定点も削る。
そこで**毎反復のあと、緩和を数スイープかけて制約へ引き戻す**。

```rust
// 制約セルは c へ、それ以外は隣接 4 セルの平均へ寄せる（重み付きラプラス緩和）
let avg = (h[i-1] + h[i+1] + h[i-dim] + h[i+dim] + 2) >> 2;
h[i] = (avg * (1000 - w[i]) + c[i] * w[i]) / 1000;
```

`conf`（信頼度）は制約からの距離 BFS で作り、「制約に近いほど変位と侵食を弱める」係数として
中点変位・侵食の両方で使う。結果として、**指定点はぴったりその標高、離れるほどシードが支配する**。

## 4. 地形進化 — 起伏のリアルさの本体（要求 1・3）

中点変位が作るのは「フラクタルな下地」でしかない。実際の地形の見え方を決めているのは
**水がどう流れたか**なので、その過程を回す。使うのは 3 つの項だけ。

```
Δh = − 河川下刻(K · √A · S / 硬さ)      … 谷を刻む、崖を作る
     + 斜面拡散(D · ∇²h)                 … 丘をなだらかにする、尾根を凸にする
     + 熱浸食(安息角超過分の再配分)        … 崩落と崖錐
```

これは地形学で標準的な stream-power + hillslope diffusion モデルの最小構成で、
**既存の `hydrology`（優先度フラッド・D8・流量集積）をそのまま入力に使える**。

### 4.1 反復の構造

```
for it in 0..iterations {
    if it % 4 == 0 { (order, downstream, area) = hydrology::flood_and_flow(h); }  // 流路は毎回作らない
    incise(h, &order, &downstream, &area, &hardness, conf);   // 河川下刻
    diffuse(h, conf);                                          // 斜面拡散
    thermal(h, &hardness, conf);                               // 熱浸食（安息角は硬さ依存）
    reproject_constraints(h, c, w);                            // 制約の再投影
}
```

流路（D8 と流量集積）は毎反復では変わらないので 4 反復に 1 回で足りる。ここが効いて、
反復あたりのコストがほぼ線形走査だけになる。

### 4.2 河川下刻

```rust
// 下流から順に。`area` は流量集積（セル数）、`isqrt` は sim-math にある。
for &i in order.iter().rev() {
    let Some(d) = downstream[i] else { continue };
    let drop_cm = h[i] - h[d];
    if drop_cm <= 0 { continue; }
    let slope_pm = drop_cm * 1000 / cell_cm;              // 勾配（1000 分率）
    let mut cut = k_incision * isqrt(area[i]) * slope_pm / 1_000_000;
    cut = cut * 255 / hardness[i].max(1) as i32;          // 硬い岩ほど削れない
    cut = cut * (1000 - conf[i]) / 1000;                  // 制約の近くは削らない
    h[i] -= cut.min(drop_cm / 2);                         // 標高の逆転を防ぐ
}
```

- √A の項が「集水域が広いほど深く刻む」を作る → **本流が深い谷、支流が浅い谷**という
  階層構造が自然に出る。これが「ノイズの塊」と「地形」を分ける最大の違い。
- 硬さで割ることで、**硬い岩を横切る所では谷が細く深い掘割（＝両岸が崖）**になり、
  軟らかい所では広い谷底になる。

### 4.3 斜面拡散（なだらかな丘）

```rust
let lap = h[n] + h[s] + h[e] + h[w] - 4 * h[i];
h[i] += lap * d_coef / 4000;
```

土壌のクリープに相当する項。これがあると尾根が**凸**に、谷頭が**凹**に丸まり、
「なだらかな丘」の見え方になる。`d_coef` を上げるほど丘陵、下げるほど痩せ尾根。
下刻（4.2）との比が地形の性格を決める唯一のつまみになる。

### 4.4 岩の硬さ場と、侵食でできる崖

```rust
// 岩体（平面ノイズ、生成時に一度だけ）× 地層（傾いた層、標高に依存するので毎反復安い計算で）
let body   = noise::fbm(x / lattice, y / lattice, 3, seed ^ K_HARD);   // -1..1
let band   = (h_cm - tilt_x * x - tilt_y * y).rem_euclid(layer_cm) * 2 / layer_cm; // 0 or 1
hardness[i] = clamp(base + body * range / FX_ONE + band * band_bonus, 0, 255);
```

熱浸食の安息角を硬さで変える。

```rust
// 硬さ 0 → 35°（tan 0.70）、硬さ 255 → 約 85°（tan 11.4）
let talus_cm = cell_m * (70 + 1070 * hardness[i] as i32 / 255);
```

ここから**崖が自然に出る**。

- 硬い層は安息角が立っているので崩れず、周りが削れて**露頭の壁**として残る
- 河川が硬い層を切る所は**両岸が崖の掘割**になる
- 硬さが標高に依存する（地層バンド）ので、削れて下の層が出ると硬さが変わり、
  **階段状の崖・河岸段丘**ができる
- 崖の下には熱浸食で運ばれた土砂が溜まり、**崖錐**になる（地表は `Scree`）

これで現行の 2 つのハックが消える。

| 現行 | v2 |
|---|---|
| `outcrop_bump_cm` — ノイズの閾値超えを段差として直接足す | 削除。崖は侵食の結果として出る |
| `thermal_erosion` が「差 250 cm 以上のペアは対象外」で崖を守る | 削除。安息角が硬さ依存になるので、守る必要がない |

### 4.5 反復数と品質

| 品質 | 中点変位 | 進化反復 | 流路再計算 |

| `Fast` | 有 | 12 | 4 反復に 1 回 |

## 5. 粗格子から 2 m へ

進化は粗格子（4〜10 m）で回し、結果を 2 m へ拡大する。粗格子で回すのは性能のためだが、
**崖を潰さずに拡大する**必要がある。

### 5.1 崖を潰さない拡大

1. 粗格子で崖エッジ（隣接差 ≥ 250 cm）を検出し、崖線として保持する
2. 拡大は**分離型 Catmull-Rom**（現行 `upsample.rs` のバイリニアだと斜面に格子縞が出る）。
   ただしタップが崖線をまたぐ場合は**崖の同じ側のタップだけで外挿**する
3. 拡大後、崖の上下 1〜2 セルの標高を「棚の高さ」（25 cm 単位に量子化）へ揃える。
   これで崖の面が平面になり、崖の上に立てる平場ができる

### 5.2 2 m でだけ足すもの

- **微地形ノイズ**: 周期 12 m / 4 m、振幅 10〜20 cm。足元がのっぺりしない
- **河岸**: 水域セルの外周 1〜2 セルを削って岸を立てる（今は水面と地面が同一標高で、
  川が「色違いの床」に見える）
- **崖錐**: 崖の下 1〜2 セルに落差の 15〜25 % を堆積、地表は `Scree`
- **耕地の畝**: `Farmland` に方向性のある周期 4 m・振幅 8 cm の波
- **河道の burn-in**: シナリオが河道を指定した場合、粗格子の段階で強制的に掘ってから
  流路を解く（指定した川筋を水が実際に流れることを保証する）

## 6. 属性（要求 8 の「全体の属性」）

### 6.1 領域ポリゴンの縁をノイズで歪める

ポリゴンをそのまま塗ると縁が直線になり、生成地形から浮く。符号付き距離をノイズで歪めてから
閾値を取る。

```
d = signed_distance_to_polygon(x, y) + fbm(x / 30, y / 30) * edge_noise_m
if d < 0 { surface = region.surface }
```

領域が無い場所はバイオーム規則で埋め、既存の森 CA 平滑化（`smooth_forests`）を最後に走らせる。

### 6.2 バイオーム = 全体の属性のデータ化

現在 `classify_surface` にハードコードされている閾値（湿度 880 で湿地、傾斜 70 % で岩…）を
`data/terrain_biomes.toml` に出し、プリセットで差し替えられるようにする。

```toml
[biome.picardy_farmland]
humidity_bias = 60                                  # 秋の長雨
rules = [                                           # 上から順に最初に当たったものを採用
  { surface = "Marsh",       humidity = [880, 1000], slope_pct = [0, 8] },
  { surface = "DenseForest", humidity = [700, 1000], slope_pct = [0, 25] },
  { surface = "Farmland",    humidity = [300, 700],  slope_pct = [0, 6] },
  { surface = "Grass" },
]
flora.DenseForest = { species = ["oak", "beech"], density_per_100m2 = 14 }
flora.Rock        = { species = ["boulder"],      density_per_100m2 = 3 }
```

砂地・海が要求にあるので `coastal_dune` / `heath` / `floodplain` も同じ形で足せる。

### 6.3 シナリオ記法（案）

```toml
[terrain]
seed = "0x4A17_C0FF_1415_0001"
size_m = 1200
cell_m = 2
biome = "picardy_farmland"
hurst = 850            # 起伏の質感。850 = なだらかな丘、550 = ごつごつした山地
relief = 120           # 中点変位の初期振幅（m）
incision = 400         # 河川下刻の強さ
diffusion = 300        # 斜面拡散の強さ
hardness_range = 500   # 岩の硬さのばらつき。大きいほど崖が出る

[[terrain.height_points]]
x = 600; y = 300; z_cm = 320; radius_m = 120       # 英軍側の微高地
[[terrain.height_points]]
x = 600; y = 900; z_cm = 0;   radius_m = 200       # 仏軍側の平坦地

[[terrain.regions]]
surface = "DenseForest"; priority = 10; edge_noise_m = 14
polygon = [[170, 0], [430, 0], [520, 1200], [180, 1200]]
```

既存の `shaping::Stamp` は互換のまま残す。

## 7. 描画（要求 5・6）

### 7.1 チャンクメッシュ

```
チャンク = 64 m × 64 m = 32 × 32 セル（2 m）
1,200 m マップ = 19 × 19 = 361 チャンク（画面内は 20〜60）
```

チャンクごとに VBO/IBO を焼き、視錐台カリングして描く。焼き直しは工兵の地形改変時のみ。
LOD は 2 m / 4 m / 8 m / 16 m の 4 段で、縁にスカート（下へ落とす帯）を付けて継ぎ目を隠す。

### 7.2 滑らかな丘と鋭い崖を 1 本のメッシュで

- セルの**角**の標高 = 周囲 4 セル中心の平均（頂点共有 → 斜面が滑らかにつながる）
- ただし**崖エッジをまたぐ角は頂点を分割**し、上側・下側で別の標高を持たせる
- 上面はセルあたり 2 三角形（対角線は短い方を選ぶ。長い方だと台形が捻れる）

### 7.3 段差の壁（要求 5）

崖エッジごとに、落差を水平な帯に分割する。

```
n = clamp(ceil(Δh / 0.5 m), 1, 8)     // 0.5 m ごとに 1 枚、最大 8 枚
```

| 帯の要素 | 決め方 |
|---|---|
| テクスチャ層 | `LUT[上面の地表][下面の地表][帯の相対高さ]`。上端は草の断面、中間は土や岩、下端は崖錐 |
| UV | 水平は崖線に沿った累積距離（テクスチャが伸びない）、垂直は帯の実高さ |
| 法線 | 帯ごとに ±8° ハッシュで振る → 平坦な板に見えない |
| 頂点色（AO） | 下の帯ほど暗い。崖の根本が締まって立体感が出る |

帯に割る理由は 3 つ: テクスチャの縦横比を保てる、帯ごとに材質を変えられる（上が草・下が岩という
実際の露頭の見え方）、AO と法線の勾配を持てる。1 枚のクアッドではどれもできない。

テクスチャは `TEXTURE_2D_ARRAY`（地表 16 種 × バリエーション + 崖壁材質）に持ち、頂点に
「地表 ID 4 個 + 重み 4 個」を載せてフラグメントで合成する。**仕様 08 章 3.2 の 47-blob Wang
タイルは不要**になる（3D メッシュと相性が悪い。境界のブレンドは頂点重みが担う）。

### 7.4 投影と深度

地形と兵士を**単一の WebGL2 コンテキスト**に統合し、正射影行列（固定ダイメトリック方向）＋
実深度バッファにする。兵士は従来どおりビルボードだが、ワールド Z を標高から取って同じ深度に載る。
これをやらないと兵士が崖の裏に隠れず、木の後ろにも回れない。
`iso.ts` の `Z_SCALE = 24 px/m` は正射影行列の成分として等価に表現でき、操作感は保てる。

### 7.5 樹木・岩（要求 6）

**配置** — 座標ハッシュによる Poisson 風散布（逐次 RNG なし、チャンク独立）

```
茎グリッド 4 m（DenseForest は 2 m）ごとに:
  h = splitmix64(seed ^ LAYER_FLORA ^ gx * K1 ^ gy * K2)
  存在判定: (h & 0xFFFF) < density(surface, humidity, slope)
  位置ジッタ: セル内 ±40 %（最小間隔が保証され、格子っぽさが消える）
  種・高さ・太さ・回転・色相: h の別ビットから
```

**ジオメトリ**（CPU で決定論的に生成、種ごとに 1 メッシュ）

| 物体 | 構成 | 三角形数 |
|---|---|---|
| 広葉樹 | 6 角柱の幹 + 切頭錐 2 段の樹冠 | 約 50 |
| 針葉樹 | 6 角柱 + 円錐 3 段 | 約 45 |
| 低木 | 交差する 3 枚の板 | 12 |
| 岩 | 正八面体を頂点ハッシュで変位した凸形 | 16〜32 |

**LOD**: L0/L1（px/m ≥ 12）はインスタンスメッシュ + 接地の楕円影、L2 はクロスビルボード 2 枚、
L3 以下は描かず地表色に樹冠色を混ぜる。

**シミュレーションとの関係**: 樹木・岩は**描画専用**。移動・遮蔽・防御は従来どおり `surface` の
効果テーブルで決まる。個々の幹を衝突体にはしない（M2 で詰めた押し合いの解が壊れ、コストにも
見合わない）。密度は `surface` から導くので見た目と効果は食い違わない。`cover` グリッドだけは
散布密度から集約し直す。

## 8. 決定論と整数演算

- `sim-terrain` は f32/f64 禁止（`tools/check_no_float.sh`）。中点変位・緩和・stream-power・
  拡散・Catmull-Rom・SDF・散布はすべて整数（cm と `Fx`）で書ける。`isqrt` は `sim-math` にある
- 疑似乱数は `splitmix64(seed ^ layer ^ x*K1 ^ y*K2)` の座標ハッシュのみ。逐次 RNG は使わない
  → チャンク単位の部分生成と全体生成がビット一致する（テストで固定する）
- メッシュ化とテクスチャ合成は web 側（f32 可）。入力が整数グリッドなので結果は決定論的
- `Terrain::hash()` に `hardness` と `step_cm` を含める

## 9. 性能見積り

1,200 m マップ（粗格子 257² ≒ 4.7 m、細格子 600² = 36 万セル）:

| 段階 | 見積り |
|---|---|
| 制約ラスタライズ + 中点変位（66 k 点） | < 10 ms |
| 硬さ場 | < 10 ms |
| 地形進化 40 反復（流路は 4 反復に 1 回） | 40〜80 ms |
| 2 m へ拡大 + 微地形 + 崖錐 | 20〜30 ms |
| 水系確定・属性分類・森 CA・崖・道路・passability | 100〜200 ms |
| 散布物（約 12 k 本） | < 20 ms |
| **合計** | **目標 < 400 ms** |

5 km マップ（粗格子は同じ 257² ≒ 20 m、細格子 2500² = 625 万セル）は仕上げ段階がセル数に
比例して 1.2〜1.8 s。現行の `Normal` 目標 1.5 s と同等で、M9 の IndexedDB キャッシュもそのまま効く。

メモリは 2 m グリッドのままなので現行と同じ（1,200 m で約 2.5 MB、5 km で約 45 MB）。
`hardness` は生成中の一時バッファで、出力には残さない。

## 10. 移行計画（M10、4 ステップ）

各ステップ単独でマージ可能・回帰しない粒度にする。

| ステップ | 内容 | 受け入れ条件 |
|---|---|---|
| **M10-a** 参照点と侵食 | 制約 + 中点変位 + 硬さ場 + 地形進化。`outcrop_bump_cm` と熱浸食の崖除外を撤去。描画は現行のまま（ヒルシェードで効果は見える） | 制約点の誤差 ≤ 5 cm（全シード）／既存シナリオ 3 本の `validate` が通る／生成 < 400 ms（1,200 m）／崖の総延長が現行以上 |
| **M10-b** メッシュ描画 | 単一 GL コンテキスト、正射影 + 実深度、チャンクメッシュ（上面 + 崖壁 1 枚） | 60 fps 維持／兵士が崖に正しく隠れる／全ズーム域でクラックが出ない |
| **M10-c** 崖の作り込み | 帯分割・材質 LUT・AO・テクスチャ配列・棚の量子化 | 崖の壁でテクスチャが伸びない／崖の上に平場ができている |
| **M10-d** 樹木・岩 | ハッシュ散布、メッシュ、LOD 3 段、`cover` 再集約 | チャンク独立生成が全体生成とビット一致／L0 で 60 fps |

途中で止めても壊れないよう、既存の `shaping` は最後まで動く状態を保つ。

## 11. 却下した案

| 案 | 却下理由 |
|---|---|
| 1 m グリッド化 | メモリと処理が 4 倍。2 m でも崖・段差・散布物は表現でき、設計が単純に保てる |
| droplet 侵食（仕様 03 章 2.2 の水力浸食） | 数万滴の逐次処理でパラメータが多く、結果の制御が難しい。stream-power は既存の D8 + 流量集積をそのまま使え、O(n)・整数・つまみが 2 つで済む |
| TPS / RBF による参照点補間 | 制約数に対して O(N³)、等高線を点列にすると破綻、浮動小数点前提。そもそも「滑らかに繋ぐだけ」では要求 1 を満たさない |
| 逆距離加重（IDW） | 参照点の周りにクレーターができ、遠方が平坦になる |
| 47-blob Wang タイルの拡張 | 3D メッシュと両立しない。頂点重みブレンドで置換 |
| ボクセル / Marching Cubes | オーバーキル。崖の棚と平場が作りにくく、整数決定論とも相性が悪い |
| 樹木を個別の衝突体にする | M2 の押し合い解が壊れる。コストに見合わない |

## 12. 残る論点

1. **仕様 00 章「3D は作らない」の読み替え** — 「固定カメラの 2.5D は維持、地形ジオメトリのみ
   3D」でよいか。崖と樹木をポリゴンで出す以上ここは避けられない
2. **テクスチャ素材の出所** — 現行のタイルアトラスは ImageGen 生成物。テクスチャ配列
   （地表 16 × バリエーション + 崖壁材質）を同じ経路で用意するか、手続き生成に戻すか
3. **`relief` パラメータの意味の変更** — 現行は「起伏の激しさ 0〜1000」だが、v2 では
   中点変位の初期振幅・ハースト指数・下刻/拡散比の 3 つに分かれる。`relief` 1 つから
   3 つを導く互換マッピングを残すか、シナリオを全部書き換えるか
4. **旧 `shaping` の扱い** — 制約記法へ移行後も恒久的に残すか
