# 提案: 地形生成 v2 — 1 m グリッド・制約駆動生成・ポリゴン地形

**状態**: 提案（未承認）。承認されたら `docs/spec/03-terrain.md` と
`docs/spec/08-rendering.md` へ本文を取り込み、ロードマップに M10 として載せる。

**要求**（発案時の言葉をそのまま要件化したもの）

1. 1 m グリッドごとに標高と属性（砂地・草原・林・森・川・海など）を持つ
2. 隣接セルとの高低差が大きい崖もあり得る
3. グリッドの間は高低差に応じて**複数枚のポリゴン**で繋がれ、適切なテクスチャが選ばれる
4. 樹木・岩は**ポリゴン**で描画される
5. シード付き乱数から一意に生成される
6. **事前に数点の標高と全体の属性を指定し、残りは自動生成**することで実在の地形を再現しやすくする

---

## 1. 現状とのギャップ

| 要求 | 現状 | 差分 |
|---|---|---|
| 1 m グリッド | 2 m（`TerrainParams::cell_m`、既定 2） | 解像度を上げるとメモリと経路探索コストが 4 倍。層分けが必要 |
| 崖 | `cliff` ビットマスクは**ある**（`compute_cliffs`、閾値 250 cm） | 崖の高さ・材質を持たず、崖線をオーサリングできない。侵食の副産物として偶発的にしか出ない |
| 段差をポリゴンで繋ぐ | **無い**。地形はマップ全体で 1 枚のクアッド（`terrain-gl.ts` の `TRIANGLE_STRIP` 4 頂点）を貼り、標高は擬似ヒルシェードの陰影だけ | 頂点変位が一切ない。崖は「暗く塗る」表現に留まっている（`shade *= 0.55`） |
| 樹木・岩 | **無い**。森は地表色/タイル絵だけ | 散布物のデータ構造もジオメトリも無い |
| シード決定論 | **達成済み**（整数演算のみ、`Terrain::hash()` で検証） | v2 でも壊さない。散布物・メッシュ化も同じ規律で書く |
| 数点の標高指定 | `shaping::Stamp::HeightRamp` のみ。**軸全体に効く 1 本のランプ**で、「この地点は +3.2 m」を書けない | 制約補間器が必要。現在の stamp は「生成してから塗り替える」ため、侵食・水系と整合しない |

補足すると、現在の描画は地形と兵士が**別の WebGL コンテキスト**（`terrainCanvas` /
`soldierCanvas`）で、地形は深度 0 の平面、兵士は `(x+y)` の擬似深度で描いている。
つまり地形と兵士の間に本物の前後関係が無い。崖や樹木を立てるなら、この分離は
先に畳む必要がある（6.6 節）。

## 2. 設計の骨子（決定 5 つ）

### D1. グリッドを 2 層に分ける

| 層 | セル | 内容 | 使う側 |
|---|---|---|---|
| **detail tier** | **1 m** | `height`(i16 cm) / `surface`(u8) / `detail`(u8) / `water`(u8) / `water_kind`(u8) / `cliff`(u8) / `step_cm`(u8) | 描画、接地標高、兵士の足元の地表効果 |
| **effect tier** | 2 m | `passability`(u8) / `cover`(u8) / `flow` | 経路探索、視線判定、AI |

**なぜ**: 経路探索と視線判定はセル数に比例する。全部を 1 m にすると M2 で詰めた
探索コストが 4 倍になる。一方、標高と地表の**見た目・接地**は 1 m でないと崖も
森の縁も 1 人分の解像度にならない。効果 tier は detail tier から面積重みで集約する
（`derive_passability` を集約版に置き換える）。

**メモリ**（会戦シナリオの実寸は既に 1,200 m 四方: `data/scenarios/*.toml`）

| マップ | detail セル数 | detail 7 グリッド | effect tier | 合計 |
|---|---|---|---|---|
| 1,200 m | 1.44 M | 11.5 MB | 1.1 MB | **12.6 MB** |
| 2,000 m | 4.0 M | 32 MB | 3.0 MB | 35 MB |
| 5,000 m | 25 M | 200 MB | 19 MB | 219 MB（**予算超過**） |

→ **1 m は「会戦場」のサイズ（既定 2,000 m 以下）でのみ既定にする**。5 km の戦域
マップは従来どおり 2 m（または 4 m）で、これは `cell_m` パラメータの延長で表現できる。
仕様 11 章のメモリ予算（地形 45 MB）にも収まる。

### D2. 「生成してから焼き込む」を「制約を解いてから細部を足す」に変える

現在の `shaping` は 14 段階の生成が終わったあとに `surface`/`height` を上書きする。
そのため、焼き込んだ丘に水は流れないし、焼き込んだ森の縁は侵食地形と無関係な直線になる。

v2 では**制約を最初に置き、生成の各段階が制約を尊重する**。

```
制約（点・等高線・崖線・領域・河道） ──┐
                                      ├─→ トレンド面（緩和法） ─→ 残差ノイズ ─→ 侵食 ─→ 水系 ─→ 1 m 詳細化 ─→ 属性 ─→ 散布
シード + パラメータ ──────────────────┘        ↑ 制約セルは各段階で再投影、制約近傍はノイズ・侵食を減衰
```

これで要求 6（数点の標高＋全体属性から実在地形を再現）が、後付けの塗りではなく
生成そのものの入力になる。

### D3. 崖を第一級のデータにする

「隣が 2.5 m 以上低ければ崖」という**事後検出**は残しつつ、
(a) シナリオが崖線をポリラインで**指定**でき、
(b) 崖の面は高さを量子化して平面に揃え、
(c) セルごとに `step_cm`（最大段差）と壁材質を持つ。
描画はこの `step_cm` を見て壁を何枚に割るかを決める（要求 3）。

### D4. 地形描画を実ポリゴンメッシュにする

固定ダイメトリックのカメラ（回転しない）は維持したまま、地形だけ**本物の 3D
ジオメトリ + 正射影 + 実深度**にする。仕様 00 章の「3D は作らない」は
「自由に回る 3D カメラは作らない」の意味として維持する — カメラの自由度は増えない。

### D5. すべてハッシュ由来にする（逐次 RNG を使わない）

セル座標・チャンク座標・散布点 ID から直接 `splitmix64` でハッシュを引く。
これにより「マップ全体を一度に生成した結果」と「チャンク単位で必要な所だけ生成した
結果」が**ビット一致**する。散布物の遅延生成、将来のマルチスレッド化、地形キャッシュ
（M9 の IndexedDB）の部分復元がすべて安全になる。テストで固定する（10 節）。

## 3. 制約（オーサリング）モデル

### 3.1 制約の種類

| 種類 | 与えるもの | 用途 |
|---|---|---|
| `height_point` | 座標 + 標高 + 影響半径 + 重み | 「英軍の立つ微高地の頂点は +3.2 m」 |
| `contour` | ポリライン + 標高 (+ 幅) | 地形図から写した等高線。**実在地形の再現はこれが主役** |
| `ridge` / `valley` | ポリライン + 標高（両端で補間）+ 鋭さ | 尾根・谷筋。単独点より遥かに形が決まる |
| `scarp`（崖線） | ポリライン + 落差 + 上下どちら側 + 材質 | 段丘崖、掘割、土塁の縁 |
| `region` | ポリゴン + 地表 + 縁のノイズ量 + 優先度 | 森・耕地・砂地・湿地の「全体の属性」 |
| `river` | ポリライン + 川幅 + 水深 + 渡渉点 | 水系を強制する（burn-in、4.5 節） |
| `biome` | プリセット名 | 領域指定の無い場所を埋める規則の束（3.3 節） |

### 3.2 シナリオ記法（案）

```toml
[terrain]
seed = "0x4A17_C0FF_1415_0001"
size_m = 1200
cell_m = 1                     # ← detail tier
biome = "picardy_farmland"     # 全体の属性プリセット
relief = 0                     # 制約が無い場所の起伏の強さ（従来どおり）

# 数点だけ標高を指定する。残りは自動生成される。
[[terrain.height_points]]
x = 600; y = 300; z_cm = 320; radius_m = 120; weight = 1000   # 英軍側の微高地
[[terrain.height_points]]
x = 600; y = 900; z_cm = 0;   radius_m = 200; weight = 1000   # 仏軍側の平坦地

# 地形図から写した等高線（あれば精度が跳ね上がる）
[[terrain.contours]]
z_cm = 150
points = [[300, 480], [520, 520], [760, 500], [980, 560]]

# 全体の属性
[[terrain.regions]]
surface = "DenseForest"; priority = 10; edge_noise_m = 14
polygon = [[170, 0], [430, 0], [520, 1200], [180, 1200]]      # アジャンクール村の森
[[terrain.regions]]
surface = "Farmland";    priority = 5;  edge_noise_m = 6
polygon = [[380, 150], [820, 150], [820, 1100], [380, 1100]]
```

既存の `shaping::Stamp` は**互換のまま残す**（後方互換。生成後の上書きとして今の
意味を保つ）。新しいシナリオは制約側で書く。

### 3.3 バイオーム = 「全体の属性」のデータ化

領域ポリゴンが無い場所を埋める規則を `data/terrain_biomes.toml` に出す。
今は `classify_surface` にハードコードされている閾値（湿度 880 で湿地、傾斜 70% で岩…）が、
バイオームごとに差し替え可能になる。

```toml
[biome.picardy_farmland]
label_ja = "北フランスの耕地帯"
humidity_bias = 60            # 秋の長雨
[[biome.picardy_farmland.rules]]     # 上から順に最初に当たったものを採用
surface = "Marsh";      humidity = [880, 1000]; slope_pct = [0, 8]
[[biome.picardy_farmland.rules]]
surface = "DenseForest"; humidity = [700, 1000]; slope_pct = [0, 25]
[[biome.picardy_farmland.rules]]
surface = "Farmland";   humidity = [300, 700];  slope_pct = [0, 6]
[[biome.picardy_farmland.rules]]
surface = "Grass"                                 # 既定
[biome.picardy_farmland.flora]
DenseForest = { species = ["oak", "beech"], density_per_100m2 = 14 }
LightForest = { species = ["oak", "birch"],  density_per_100m2 = 5 }
Scrub       = { species = ["gorse"],         density_per_100m2 = 9 }
Rock        = { species = ["boulder"],       density_per_100m2 = 3 }
```

砂地・海が要求に挙がっているので、`coastal_dune` / `heath` / `floodplain` /
`alpine` のプリセットも同じ形で足せる。

## 4. 生成パイプライン v2

粗格子は 8 m（1,200 m マップで 150²）、詳細は 1 m。**重い処理はすべて粗格子で回し、
1 m は「拡大 + 局所ディテール」だけにする**のが性能の要。

| # | 段階 | 格子 | 備考 |
|---|---|---|---|
| 0 | 制約の正規化・ラスタライズ | 8 m | 値 `c[]` と重み `w[]` の 2 枚を作る |
| 1 | **トレンド面の求解**（4.1） | 8 m | 重み付きラプラス緩和のマルチグリッド |
| 2 | 信頼度場（4.2） | 8 m | 制約からの距離 BFS → ノイズ・侵食の減衰係数 |
| 3 | 残差ノイズ加算 | 8 m | 既存 `noise::warped_fbm` / `ridged`。振幅 ×(1−信頼度) |
| 4 | 熱侵食 + droplet 侵食 | 8 m | 既存 `thermal_erosion` を粗格子へ。droplet を初導入（安い格子なので実用的） |
| 5 | 河道 burn-in（4.5） | 8 m | 指定河道を強制的に掘る |
| 6 | 窪地埋め・D8・流量集積・河川分類 | 8 m | 既存 `hydrology` をそのまま |
| 7 | **8 m → 1 m 拡大**（4.3） | 1 m | Catmull-Rom（分離型）。制約セルは再投影 |
| 8 | 1 m 固有ディテール（4.4） | 1 m | 微地形・畝・轍・河岸・崖錐 |
| 9 | **崖の確定**（5 章） | 1 m | 崖線 + 自然崖、量子化、棚づくり、`step_cm`・材質 |
| 10 | 属性の解決（4.6） | 1 m | 領域 SDF（ノイズ歪み）> バイオーム規則。森は CA 平滑化（既存） |
| 11 | 散布物（6 章） | — | ハッシュ Poisson。樹木・岩・茂み |
| 12 | 効果 tier の集約 | 2 m | `passability` / `cover`（散布物密度込み） |
| 13 | 道路・橋 | 1 m | 既存 `roads` を 1 m へ（コスト場は effect tier で探索） |
| 14 | 会戦地評価・検証 | — | 既存 `battle_site` + 制約誤差レポート（10 章） |

### 4.1 トレンド面: 重み付きラプラス緩和（提案の中核）

「数点だけ指定して、残りをもっともらしく埋める」ための解法。

制約セルでは `h = c`、それ以外では「隣接 4 セルの平均に近づく」という条件を
同時に満たす場を求める。これは重み付きの離散ポアソン方程式で、Gauss–Seidel 緩和を
マルチグリッド（V-cycle）で回すと O(n) で解ける。

```rust
// 1 回の緩和スイープ（整数、Fx 不要 — cm のまま解ける）
fn relax(h: &mut [i32], c: &[i32], w: &[u16], dim: usize) {
    for y in 1..dim - 1 {
        for x in 1..dim - 1 {
            let i = y * dim + x;
            let avg = (h[i - 1] + h[i + 1] + h[i - dim] + h[i + dim] + 2) >> 2;
            // w = 1000 なら制約そのまま、0 なら純粋な平均（＝最も滑らかな面）
            h[i] = (avg * (1000 - w[i] as i32) + c[i] * w[i] as i32) / 1000;
        }
    }
}
```

V-cycle: 8 m 格子（150²）→ 16 m → 32 m → 64 m へ制限し、各段で数回スイープして
補間で戻す。4 段 × 各 4 スイープで残差 1 cm 未満に収束する（150² で概算 200 万演算、
**5 ms 未満**）。

**なぜ緩和法か。** 候補は 3 つあった。

| 手法 | 判定 |
|---|---|
| TPS / RBF 補間（薄板スプライン） | 制約 N 点で密行列 O(N³)。等高線を点列にすると N が数千になり破綻。浮動小数点前提で `check_no_float.sh` に反する。**却下** |
| 逆距離加重（IDW） | 実装は最も簡単だが、制約点の周りに「クレーター」ができ、遠方が平坦になる。地形として不自然。**却下** |
| **重み付きラプラス緩和（マルチグリッド）** | O(n)、制約数に依存しない。点・線・面の制約を同じ枠で扱える。整数で書ける。地図端・海面を境界条件にできる。**採用** |

`weight` を 1000 未満にすれば「だいたいこの高さ」という緩い制約になり、
`radius_m` はラスタライズ時に重みを距離で減衰させて表現する。

### 4.2 信頼度場 — 制約と手続き生成の混ぜ方

制約セルからの距離を BFS で求め、`confidence = clamp(1 - dist / falloff, 0, 1)` とする。

- 残差ノイズの振幅 ×= (1 − confidence)
- 侵食の移動量 ×= (1 − confidence)

これで「指定した点はぴったりその高さ、離れるほど手続き生成が支配する」が成立する。
指定点の誤差はテストで ≤ 5 cm を保証する（10 章）。

### 4.3 8 m → 1 m の拡大

現在の `upsample.rs` は**バイリニア**。倍率 4 なら問題ないが、倍率 8 で使うと
斜面に粗格子の格子縞（C⁰ 不連続に由来する折れ線）がはっきり出る。
**分離型 Catmull-Rom**（横 4 タップ → 縦 4 タップ）に差し替える。C¹ 連続で、
整数演算のまま書ける（係数は 1/2 の冪で表せる形に丸める）。コストは
1.44 M セル × 8 積和 ≒ 12 M 演算 で、実測で数十 ms のオーダー。

### 4.4 1 m でしか作れないもの

粗格子には無い、**1 m 解像度の存在意義**がこの段階。

- **微地形ノイズ**: 周期 12 m / 3 m、振幅 10〜25 cm。歩兵の足元がのっぺりしない
- **耕地の畝**: `Farmland` セルに方向性のある周期 1.5 m・振幅 8 cm の波（畝の向きは区画ごとにハッシュで決定）。アジンクールの「耕された泥」が視覚的に効く
- **道の轍**: `Road` に沿って −10 cm の溝 2 本
- **河岸**: 水域セルの外周 1〜3 セルを削り、岸を立てる（今は水面と地面が同一標高で、川が「色違いの床」に見える）
- **崖錐（scree）**: 崖の下 2〜4 セルに堆積を置き、地表を `Scree` にする

### 4.5 河道の burn-in

指定した河道ポリラインに沿って粗格子の標高を強制的に下げてから窪地埋め・D8 を回す
（DEM 水文解析で言う stream burning）。これで「シナリオが指定した川筋を水が実際に
流れる」ことが保証され、川の位置と流量集積が矛盾しない。既存の
`hydrology::flood_and_flow` はそのまま使える。

### 4.6 属性の解決 — 領域の縁をノイズで歪める

領域ポリゴンをそのまま塗ると縁が直線になり、手続き生成の地形から浮く。
そこで**符号付き距離（SDF）をノイズで歪めてから閾値**を取る。

```
d = signed_distance_to_polygon(x, y)            // 内側が負、m 単位
d += fbm(x / 30, y / 30) * edge_noise_m         // 縁だけが揺れる
if d < 0 { surface = region.surface }
```

森の縁が有機的になり、しかも制御はポリゴンのままという両立ができる。
優先度順に領域を適用し、領域が無い場所はバイオーム規則（3.3）で埋める。
森の CA 平滑化（既存 `smooth_forests`）はその後に走らせる。

## 5. 崖の作り方（要求 2・3 の生成側）

1. **崖線の合成**: 指定された `scarp` 制約と、`|Δh| ≥ 250 cm` の自然発生崖を
   同じ「崖エッジ集合」に入れる。
2. **段差の量子化**: 崖エッジの上側・下側それぞれで、崖線に沿った帯（幅 2〜3 セル）の
   標高を**25 cm 単位に量子化した棚の高さ**に揃える。これをやらないと崖の面が
   ギザギザになり、壁ポリゴンが 1 セルごとに別々の傾きを向く。棚を作ることで
   「崖の上に立てる平場」ができ、戦術的にも意味が出る（弓兵を置ける）。
3. **崖錐**: 崖の下 2〜4 セルに落差の 15〜25 % を堆積させ、`Scree` を置く。
4. **書き出し**: `cliff`（4 方向ビット、既存）に加えて
   - `step_cm[i]`: そのセルの 4 近傍への最大段差（cm、上限 255 → 2.55 m 超は 255 に飽和させ、壁側で実測値を再計算）
   - `wall_material[i]`: 4 ビット。上下の地表と落差から LUT で決める（土 / 草付き土 / 岩 / 崖錐 / 砂）
5. **通行**: 崖エッジは通行不能（既存どおり）。ただし崖線に**スロープ（登り口）**を
   ハッシュで 1 本以上開ける。開けないと `validate` の連結性チェックに落ちる。

## 6. 描画 v2

### 6.1 チャンクメッシュ

```
チャンク = 64 m × 64 m = 4,096 セル（1 m）
1,200 m マップ = 19 × 19 = 361 チャンク（画面内は 20〜60）
```

チャンクごとに VBO/IBO を焼き、視錐台カリングして描く。焼き直しは工兵の地形改変時のみ。

### 6.2 頂点の作り方 — 滑らかな丘と鋭い崖の両立

- セルの**角**の標高 = 周囲 4 セル中心の平均（頂点を共有 → 斜面が滑らかにつながる）
- ただし**崖エッジをまたぐ角は頂点を分割**し、上側集合・下側集合で別々の標高を持たせる
- 上面はセルあたり 2 三角形（対角線は短い方を選ぶ。長い方だと台形が捻れる）

これが「丘は滑らか、崖は鋭い」を 1 本のメッシュで出す最小の仕掛け。

### 6.3 段差の壁 — 「高低差に応じた複数枚のポリゴン」（要求 3）

崖エッジごとに、落差 Δh を水平な帯に分割する。

```
n = clamp(ceil(Δh / 0.5 m), 1, 8)     // 0.5 m ごとに 1 枚、最大 8 枚
```

帯ごとに:

| 帯の要素 | 決め方 |
|---|---|
| テクスチャ層 | `LUT[上面の地表][下面の地表][帯の相対高さ]` → 上端は「草の断面」、中間は土や岩、下端は崖錐 |
| UV | 水平は崖線に沿った累積距離（テクスチャが伸びない）、垂直は帯の実高さ |
| 法線 | 帯ごとに ±8° ほどハッシュで振る → 平坦な板に見えない |
| 頂点色（AO） | 下の帯ほど暗く。崖の根本が締まって見え、立体感が段違いに上がる |

**分割する理由**は 3 つ: (a) テクスチャの縦横比を保てる、(b) 帯ごとに材質を変えられる
（上が草、下が岩という実際の露頭の見え方）、(c) 頂点で AO と法線の勾配を持てる。
1 枚のクアッドで済ませると、この 3 つが全部できない。

### 6.4 テクスチャ

`TEXTURE_2D_ARRAY`（層 = 地表 16 種 × バリエーション 2〜4、512²）で持ち、
頂点に「地表 ID 4 個 + 重み 4 個」を載せてフラグメントで合成する。
**仕様 08 章 3.2 の 47-blob Wang タイルは不要になる**（3D メッシュとは相性が悪く、
遷移パターンの管理コストも高い）。境界のブレンドは頂点重みが担う。

### 6.5 樹木・岩（要求 4）

**配置** — ハッシュ Poisson（逐次 RNG なし、チャンク独立）

```
茎グリッド 4 m（DenseForest は 2 m）ごとに:
  h = splitmix64(seed ^ LAYER_FLORA ^ gx * K1 ^ gy * K2)
  存在判定: (h & 0xFFFF) < density(surface, humidity, slope)
  位置ジッタ: セル内 ±40 %（最小間隔が保証され、格子っぽさが消える）
  種・高さ・太さ・回転・色相: h の別ビットから
```

**ジオメトリ**（CPU で決定論的に生成、種ごとに 1 メッシュ）

| 物体 | 構成 | 三角形数 |
|---|---|---|
| 広葉樹 | 6 角柱の幹 + 切頭錐 2 段の樹冠 | 約 50 |
| 針葉樹 | 6 角柱 + 円錐 3 段 | 約 45 |
| 低木 | 交差する 3 枚の板 + 頂点ノイズ | 12 |
| 岩 | 正八面体を頂点ハッシュで変位した凸形 | 16〜32 |

**LOD**

| LOD | px/m | 表現 |
|---|---|---|
| L0/L1 | ≥ 12 | インスタンスメッシュ + 接地の楕円影 |
| L2 | 3〜12 | クロスビルボード 2 枚 |
| L3 以下 | < 3 | 描かない。地表色に樹冠色を混ぜる（現行の焼きテクスチャ相当） |

**シミュレーションとの関係**: 樹木は**描画専用**。移動・遮蔽・防御はこれまでどおり
`surface`（`LightForest` / `DenseForest`）の効果テーブルで決まる。個々の幹を
衝突体にはしない（M2 で詰めた押し合いの解が壊れ、コストにも見合わない）。
密度は `surface` から導くので、見た目と効果が食い違うことはない。
`cover` グリッドだけは散布密度から集約し直して整合させる。

### 6.6 投影と深度 — 地形と兵士を 1 つのコンテキストに

現状は地形キャンバスと兵士キャンバスが別コンテキストで、地形は深度 0 の平面、
兵士は `(x+y)/2W` の擬似深度。**崖と樹木を立てるとこの構成では破綻する**
（兵士が崖の裏に隠れない、木の後ろに回れない）。

- 1 つの WebGL2 コンテキストに統合し、**正射影行列**（固定ダイメトリック方向）＋
  実深度バッファにする
- 兵士は従来どおりビルボードだが、ワールド Z を 1 m 標高から取り、同じ深度に載る
- 半透明（影・エフェクト）は深度書き込み OFF の後段パス（仕様 08 章 1.1 の方針どおり）

`iso.ts` の `Z_SCALE = 24 px/m` は正射影行列の成分として等価に表現でき、
既存のズーム・カメラ操作の見た目は保てる。

### 6.7 描画予算（1,200 m マップ、画面内 40 チャンク想定）

| 要素 | 三角形 | 備考 |
|---|---|---|
| 上面 | 40 × 8,192 = 328 k | LOD で遠方チャンクは 1/4〜1/64 に減る |
| 壁 | 5〜20 k | 崖の総延長に比例 |
| 樹木・岩（L0/L1） | 3,000 本 × 50 = 150 k | 視錐台内のみ、インスタンシング |
| 兵士 | 50 k インスタンス | 既存どおり |

WebGL2 で 60 fps に十分収まる規模。チャンク焼きは 1 フレーム 1〜2 枚に制限する。

## 7. 「実在の地形を再現する」ワークフロー

アジンクールを例にすると、現状は `height_ramp` 1 本（南が 5 m 高い）だけだが、v2 では:

1. 地形図・航空写真から**等高線を 2〜4 本トレース**して `contours` に置く
2. 会戦の記述から効く地点を `height_points` で数点固定（英軍正面の微高地、仏軍側の低み）
3. 森・耕地・泥濘を `regions` のポリゴンで置く（縁はノイズで歪む）
4. 川があれば `rivers` で河道を指定（burn-in で水系が従う）
5. `biome` で気候由来の既定値（湿度バイアス、植生規則、樹種）を選ぶ
6. **残りはシードから自動生成** — 微高地の形、藪の散り方、木の 1 本 1 本

検証は `sim-headless` にサブコマンドを足す:

```
cargo run -p sim-headless -- terrain-report --scenario agincourt_1415
  制約誤差: 最大 3 cm / 平均 1 cm（12 制約）
  通行可能: 91 %  最大連結成分: 99 %
  崖: 総延長 340 m（最大落差 4.2 m）
  河川: 到達 OK   生成: 620 ms   メモリ: 12.6 MB
```

**シードを変えると細部だけが変わり、制約は動かない** — これがこの設計の要点で、
テストで固定する。

## 8. 決定論と整数演算

- `sim-terrain` は f32/f64 禁止（`tools/check_no_float.sh`）。緩和法・Catmull-Rom・
  SDF・ハッシュ Poisson はいずれも整数（cm と `Fx`）で書ける。除算はシフトへ寄せる
- 疑似乱数は `splitmix64(seed ^ layer_id * K0 ^ x * K1 ^ y * K2)` の座標ハッシュのみ。
  逐次 RNG は使わない（D5）
- メッシュ化とテクスチャ合成は web 側（f32 可）。入力が整数グリッドなので結果は決定論的
- `Terrain::hash()` は detail tier と `step_cm` を含む形に拡張する

## 9. 性能見積り（1,200 m × 1 m）

| 段階 | 格子 | 見積り |
|---|---|---|
| 制約ラスタライズ + 緩和（V-cycle 4 段） | 8 m / 150² | < 10 ms |
| 残差ノイズ | 8 m | < 5 ms |
| 侵食（熱 30 + droplet 20 k） | 8 m | 60〜120 ms |
| 水系（burn-in / flood / D8 / 集積） | 8 m | < 20 ms |
| 8 m → 1 m 拡大（Catmull-Rom） | 1.44 M | 60〜100 ms |
| 1 m ディテール + 崖 + 属性 + 森 CA | 1.44 M | 200〜350 ms |
| 散布物（約 40 k 本） | — | < 20 ms |
| 効果 tier 集約・道路・検証 | 2 m | 50〜80 ms |
| **合計** | | **目標 < 800 ms** |

M9 の IndexedDB キャッシュはそのまま効く。

## 10. 移行計画（M10 として 5 ステップ）

各ステップ単独でマージ可能・回帰しない粒度にする。

| ステップ | 内容 | 受け入れ条件 |
|---|---|---|
| **M10-a** 制約ソルバ | `constraints.rs` + `relax.rs`、`cell_m = 1` 対応、効果 tier 集約。描画は現行のまま | 制約点の誤差 ≤ 5 cm（全シード）／既存シナリオ 3 本の `validate` が通る／生成 < 800 ms |
| **M10-b** メッシュ描画 | 単一 GL コンテキスト、正射影 + 実深度、チャンクメッシュ（上面のみ、崖は壁 1 枚） | 60 fps 維持／兵士が崖に正しく隠れる／全ズーム域でクラックが出ない |
| **M10-c** 崖の作り込み | 量子化・棚・崖錐・`step_cm`・壁の帯分割・テクスチャ配列・AO | 崖線を指定したシナリオで意図した段差が出る／壁のテクスチャが伸びない |
| **M10-d** 散布物 | ハッシュ Poisson、樹木・岩メッシュ、LOD 3 段、`cover` 再集約 | チャンク独立生成が全体生成とビット一致／L0 で 60 fps |
| **M10-e** シナリオ移行 | アジンクール / クレシー / バノックバーンを制約記法へ。`terrain-report` | 既存の地形テスト（高低関係・森の位置）が制約版でも通る |

途中で止めても壊れないよう、`cell_m = 2` と旧 `shaping` は最後まで動く状態を保つ。

## 11. 却下した案

| 案 | 却下理由 |
|---|---|
| ボクセル / Marching Cubes | オーバーキル。崖の「棚」と平場が作りにくく、整数決定論との相性も悪い |
| 47-blob Wang タイル（仕様 08 章 3.2）の拡張 | 3D メッシュと両立しない。頂点重みブレンドで置き換える |
| TPS / RBF による制約補間 | 制約数に対して O(N³)、等高線を扱うと破綻、浮動小数点前提 |
| 全マップ 5 km を 1 m 化 | 25 M セル ≒ 219 MB でメモリ予算超過。会戦場サイズに限定する |
| 樹木を個別の衝突体にする | M2 の押し合い解が壊れる。コストに見合わない。地表効果で表現する |
| 侵食を 1 m で回す | droplet を 1.44 M セルで数万滴流すと生成時間が数秒。粗格子で十分な形が出る |

## 12. 残る論点（要判断）

1. **1 m の既定化の範囲** — 会戦シナリオ（≤ 2 km）は 1 m、戦域マップは 2 m という
   二本立てでよいか。それとも常に 1 m にして最大サイズを 2 km に制限するか
2. **仕様 00 章「3D は作らない」の書き換え** — 「固定カメラの 2.5D」は維持しつつ
   地形ジオメトリのみ 3D にする、と読み替えてよいか
3. **テクスチャ素材の出所** — 現行のタイルアトラスは ImageGen 生成物。
   テクスチャ配列（地表 16 × バリエーション + 崖壁材質）を同じ経路で用意するか、
   手続き生成に戻すか
4. **旧 `shaping` の扱い** — 制約記法へ完全移行した後に削除するか、恒久的に残すか
