# 03. 地形生成

## 1. グリッド構成

地形は解像度の異なる複数のグリッドとして保持する。すべて `u64` のワールドシードから
決定論的に生成される。

| グリッド | セル | 5km 四方での寸法 | 型 | サイズ | 内容 |
|---|---|---|---|---|---|
| `height` | 2 m | 2500 × 2500 | `i16`（cm、±327 m） | 12.5 MB | 標高 |
| `surface` | 2 m | 2500 × 2500 | `u8` | 6.25 MB | 地表タイプ ID |
| `water` | 2 m | 2500 × 2500 | `u8`（深さ 10 cm 単位、0 = 陸） | 6.25 MB | 水深 |
| `passability` | 2 m | 2500 × 2500 | `u8`（0 = 不通、255 = 最速） | 6.25 MB | 通行コスト（導出値） |
| `cliff` | 2 m | 2500 × 2500 | `u8`（bitmask 4 方向） | 6.25 MB | 崖エッジ |
| `flow` | 8 m | 625 × 625 | `u32` | 1.5 MB | 流量集積（生成中間物、河川描画にも使う） |
| `cover` | 8 m | 625 × 625 | `u8` | 0.4 MB | 視界遮蔽率（射線判定用の粗い版） |

合計約 45 MB。wasm のリニアメモリに収まる。マップサイズを 8 km にすると 2.5 倍に
なるので、その場合は `height` を 4 m 解像度に落とす（設定で切り替え）。

**なぜ 2 m か。** 兵士は 0.5〜1 m 間隔で立つので、1 m 解像度なら「1 人 1 セル」に
なるが、5 km 四方で 2500 万セルとメモリが厳しい。2 m なら 1 セルに 2〜4 人が乗る
密度で、移動コスト・遮蔽・地表効果の表現には十分。マップチップの描画単位もこれに
合わせる（1 タイル = 2 m 四方）。

## 2. 生成パイプライン

すべての段階が決定論的で、シードとパラメータのみに依存する。

```
Seed + TerrainParams
  │
  ├─ 1. ベース標高      ドメインワープ fBm value noise
  ├─ 2. 山脈・丘陵      ridged multifractal を加算
  ├─ 3. 海の設定        海面レベルを決め、海岸線を確定
  ├─ 4. 熱浸食          安息角を超える斜面を崩す（N 反復）
  ├─ 5. 水力浸食        簡易 droplet erosion（谷を刻む、N 反復）
  ├─ 6. 窪地の処理      priority-flood で湖を確定、残りは排水
  ├─ 7. 流向・流量      D8 フロー方向 → 流量集積
  ├─ 8. 河川            流量が閾値超のセルを河川化、川幅と深さを流量から決定
  ├─ 9. 湿度            河川・湖からの距離と標高から湿度場を作る
  ├─10. 植生・地表      標高・傾斜・湿度から地表タイプを割り当て
  ├─11. 崖              隣接セル間の高度差が閾値超のエッジを崖としてマーク
  ├─12. 道路            拠点間を勾配コスト A* で結ぶ、河川との交点に橋
  ├─13. 通行コスト      地表・傾斜・水深から passability を導出
  └─14. 会戦地の評価    展開可能な平坦地を探し、初期配置候補を提案
```

### 2.1 ベース標高（段階 1〜2）

固定小数点の value noise を使う（Perlin/Simplex を整数化したもの）。

```rust
/// 格子点のハッシュから整数勾配を引き、Hermite 補間する
fn value_noise_fx(x: Fx, y: Fx, seed: u64) -> Fx;

/// オクターブを重ねる
fn fbm_fx(x: Fx, y: Fx, octaves: u8, lacunarity: Fx, gain: Fx, seed: u64) -> Fx;

/// ドメインワープ: 座標自体をノイズでずらす。等方的でない自然な形になる
fn warped_fbm(x: Fx, y: Fx, warp: Fx, ...) -> Fx {
    let wx = x + fx_mul(warp, fbm_fx(x, y, 3, .., seed ^ 0xA1));
    let wy = y + fx_mul(warp, fbm_fx(x, y, 3, .., seed ^ 0xB2));
    fbm_fx(wx, wy, 6, .., seed)
}
```

山脈は ridged multifractal（`1 - |noise|` を重ねる）で稜線を作る。

### 2.2 浸食（段階 4〜5）

**熱浸食**: 隣接セルとの高度差が安息角（既定 tan 35°）を超えたら、超過分の一部を
低い側へ移す。これを 30〜60 反復。急斜面が崩れて崖の下に崖錐ができる。

**水力浸食**: droplet 法。ランダムな位置（シードから決定的に生成）に水滴を置き、
勾配に沿って流し、速度に応じて土砂を削り・運び・堆積させる。5 km マップで
50,000〜200,000 滴。これで谷が刻まれ、下流に扇状地ができる。

浸食は生成時間の大半を占めるので、**wasm では反復回数を落とし、品質モードを設ける**
（下記 5 章）。

### 2.3 水系（段階 6〜8）

1. **priority-flood** で窪地を埋め、埋めた領域を湖としてマーク（埋めた深さが水深）。
2. **D8** で各セルの流向を決める（8 近傍で最も低い方向）。
3. 上流から順に **流量集積**（各セルの流量 = 自分の降水量 + 流れ込む上流の合計）。
   トポロジカル順に処理するので O(n)。
4. 流量が閾値を超えたセルを **河川** にする。
   - 川幅 `w = k * sqrt(flow)`（1.5 m 〜 60 m）
   - 水深 `d = k2 * flow^0.4`（0.2 m 〜 8 m）
5. 河川が海または地図外に到達することを検証する（内陸で消える川はバグ）。

### 2.4 地表タイプ（段階 10）

| ID | 地表 | 出現条件 |
|---|---|---|
| 0 | `DeepWater` | 水深 > 1.5 m |
| 1 | `ShallowWater` | 水深 0.3〜1.5 m（徒渉可） |
| 2 | `Ford` | 河川で水深 < 0.4 m かつ川底が硬い（渡渉点） |
| 3 | `Marsh` | 湿度 高 かつ 傾斜 < 3° |
| 4 | `Mud` | 湿度 中高 かつ 傾斜 < 5°（降雨後に拡大する） |
| 5 | `Grass` | 既定 |
| 6 | `Meadow` | 湿度 中 かつ 傾斜 < 8°（背の高い草、視界をやや遮る） |
| 7 | `Farmland` | 平坦かつ道路・拠点の近傍 |
| 8 | `Scrub` | 湿度 低〜中、傾斜 中 |
| 9 | `LightForest` | 湿度 中高、傾斜 < 25° |
| 10 | `DenseForest` | 湿度 高、傾斜 < 25°、面積が一定以上 |
| 11 | `Rock` | 傾斜 > 30° または高標高 |
| 12 | `Scree` | 崖の直下（熱浸食の堆積） |
| 13 | `Sand` | 海岸線の帯 |
| 14 | `Road` | 段階 12 で敷設 |
| 15 | `Bridge` | 道路が河川と交差する点 |

森は単純な閾値だけだと斑になるので、**セルオートマトンで 3 反復平滑化**して
まとまった林にし、境界を自然にする。

### 2.5 崖（段階 11）

隣接セル（4 近傍）の標高差が **2.5 m 以上**なら、そのエッジを崖としてマークする。
崖エッジは通行不能。`cliff` グリッドは 4 ビットで N/E/S/W の崖有無を持つ。

崖は描画にも使う（08 章）。タイル間に垂直な崖面のクアッドを立てる。

### 2.6 会戦地の選定（段階 14）

「ここで会戦をやるとおもしろい」場所を自動で探す。評価関数:

- **展開可能面積**: 両軍が横隊を組める連続した通行可能地の幅（1,000 m 以上が望ましい）
- **地形の非対称性**: 一方に高地、一方に川や森があると戦術的に意味が出る
- **ボトルネックの存在**: 橋・渡渉点・森の隙間があると工兵と陣形の判断が効く
- **視界**: 開けすぎず、閉じすぎず

上位候補を数か所返し、シナリオはそのうちの 1 つを選んで両軍の初期配置を決める。

## 3. 地形が兵士に与える影響

`data/terrain_surfaces.toml` で定義する。すべての値は倍率（1000 = 等倍）。

| 地表 | 移動 | 隊列維持 | 遮蔽 | 防御 | 疲労 | 騎兵 |
|---|---|---|---|---|---|---|
| `Road` | 1150 | 1100 | 0 | 1000 | 900 | 可 |
| `Grass` | 1000 | 1000 | 0 | 1000 | 1000 | 可 |
| `Farmland` | 950 | 950 | 50 | 1000 | 1050 | 可 |
| `Meadow` | 900 | 900 | 150 | 1000 | 1100 | 可 |
| `Scrub` | 800 | 750 | 250 | 1000 | 1200 | 減速 |
| `LightForest` | 650 | 500 | 600 | 1100 | 1300 | 突撃不可 |
| `DenseForest` | 400 | 250 | 900 | 1200 | 1600 | 進入不可 |
| `Mud` | 500 | 600 | 0 | 900 | 1900 | 減速大 |
| `Marsh` | 350 | 400 | 200 | 800 | 2200 | 進入不可 |
| `ShallowWater` | 400 | 300 | 0 | 600 | 1800 | 減速大 |
| `Ford` | 550 | 400 | 0 | 700 | 1500 | 可 |
| `DeepWater` | 0 | — | — | — | — | 不可 |
| `Rock` | 700 | 600 | 100 | 1100 | 1400 | 減速大 |
| `Scree` | 600 | 450 | 0 | 1000 | 1500 | 不可 |
| `Sand` | 850 | 850 | 0 | 1000 | 1250 | 減速 |

**防御 600（浅瀬）が意味するもの。** 川を渡っている最中の部隊は隊列が崩れ（維持 300）、
防御が 4 割落ちる。渡渉中に襲われると壊滅する。これがクレシー以前から
中世会戦の定番だった「渡渉点を押さえる」戦術の理由で、仕様としてそのまま効く。

### 3.1 傾斜の効果

```
上り勾配 θ:  速度 ×= 1 - 1.8·tanθ     （tanθ > 0.55 で移動不可）
             疲労 ×= 1 + 3.0·tanθ
下り勾配 θ:  速度 ×= 1 + 0.4·tanθ     （tanθ < -0.35 で転倒判定が入る）
             突撃モメンタム += 高低差に比例
```

**高地の価値**は 3 つの経路で自然に出る。
1. 上ってくる側が疲労する
2. 下る側の突撃にモメンタムボーナス
3. 見晴らしがよい = 指揮官の `Blackboard` の情報が正確になる（05 章）

意図的なボーナス値を足すのではなく、この 3 つの合成として現れるようにする。

### 3.2 天候

シナリオで指定する。地表を動的に書き換える。

| 天候 | 効果 |
|---|---|
| `Clear` | 基準 |
| `Rain` | `Farmland`/`Grass` の一部が `Mud` 化（累積時間で拡大）。弓の射程 −10%、弩の弦が伸びて威力 −15% |
| `HeavyRain` | 泥化が加速。視界 −40%。射撃ほぼ不能 |
| `Fog` | 視界半径を 60〜150 m に制限。指揮官の情報が大幅に劣化 |
| `Snow` | 移動 −20%、疲労 +30%、視界 −20% |

泥化は実際にアジンクールで決定的だったので、**重装備の兵士ほど泥で速度と疲労が
悪化する**（装備重量が効く）ようにする。

### 3.3 シナリオによる地形整形

手続き生成は「それらしい野原」までしか作れない。**史実の会戦を再現するには、
その会戦固有の地勢を上から焼き込む**必要がある——アジンクールなら、狭まって
いく 2 つの森の縁、雨で泥濘化した耕地、英軍側へのわずかな登り。

シナリオは生成パラメータに加えて、生成直後に 1 回だけ適用する整形を並べて
書ける（`sim_terrain::shaping`）。書き換えるグリッドは 4 節の動的変更と同じ
`surface` / `height` で、適用後に崖と通行コストを取り直す。

| 整形 | 意味 |
|---|---|
| `surface_rect` | 軸並行の矩形を 1 種類の地表で塗る（耕地、泥濘の帯） |
| `surface_belt` | 線分から一定距離以内を塗る帯（斜めに走る森の縁） |
| `height_ramp` | 軸に沿って標高へ緩い勾配を足す（会戦場全体の傾き） |
| `drain` | 矩形から水を抜く（水深 0・地表を指定のものに） |

適用順に意味がある（後の整形が前の整形を上書きする）。水域のセルは塗り替え
ない——水深グリッドと地表が食い違うと描画も水系ロジックも壊れるため。
シナリオが「ここは乾いた会戦場だ」と決めた区画から手続き生成の湖を消すには、
先に `drain` で水を抜く。**水は騎兵を完全に止める**（`cavalry_mult` が 0）ので、
展開地に湖が残ったまま騎兵を置くと、動けない兵の塊ができて隊列が押し合いで
自壊する。

`height_ramp` は矩形ではなく軸全体に効き、範囲外は端の値で一定になる。矩形に
限ると境界が崖になってしまうため。

天候（3.2 節）が未実装の間、「雨が降ったあと」は結果である泥濘を
`surface_rect` で直接焼き込むことで代用する。

## 4. 地形の動的変更

工兵の作業（07 章）と戦闘の結果で地形グリッドは書き換わる。

| 変更 | 対象グリッド | 例 |
|---|---|---|
| 架橋 | `surface` → `Bridge`, `passability` 上昇 | 川に仮橋 |
| 伐採 | `surface` → `Grass`, `cover` 低下 | 射界の確保 |
| 掘削 | `height` −, `surface` → `Mud`, `passability` 低下 | 堀 |
| 土塁 | `height` +150 cm, `cliff` マーク | 防塁 |
| 杭列 | `Structure` として重畳（グリッド外） | 対騎兵 |
| 踏み荒らし | `surface` `Grass` → `Mud`（多数の通過で累積） | 会戦後半の泥濘化 |

**踏み荒らし**は自動で起きる。各セルの通過人数を数え、閾値を超えると
`Grass` → `Mud` に劣化する（湿度が高いほど早い）。会戦の後半になるほど
中央が泥沼になり、機動が鈍る。

## 5. 生成の性能

| 品質 | 浸食反復 | droplet 数 | 5km 生成時間目標 |
|---|---|---|---|
| `Fast` | 熱 10 / 水 0 | 0 | < 300 ms |
| `Normal` | 熱 30 / 水 3 | 50,000 | < 1.5 s |
| `High` | 熱 60 / 水 8 | 200,000 | < 6 s |

生成は Sim Worker 内で行い、進捗を段階ごとに報告して UI にプログレスを出す。
生成済み地形は `IndexedDB` にシードをキーにしてキャッシュしてよい（グリッドの
生バイトを圧縮して保存）。

## 6. パラメータ

`TerrainParams`（シナリオで指定、すべて省略可）:

```toml
[terrain]
seed = 0x5EED_1234
size_m = 5000            # 2000..8000
cell_m = 2               # 2 または 4
quality = "Normal"

relief = 0.45            # 0=平原 1=山岳。起伏の激しさ
sea = "none"             # "none" | "edge_north" | "edge_east" | "bay"
sea_level_m = 0.0
river_density = 0.5      # 0=なし 1=網目状
forest_cover = 0.35      # 森の被覆率
marsh_bias = 0.15        # 湿地のできやすさ
road_count = 3
weather = "Clear"
```
