# 12. ロードマップ

各マイルストーンには**受け入れ条件**を置く。条件を満たさないまま次へ進まない。
特に性能は早い段階から実際の体数で測る（11 章 7 節）。

## M0 — 基盤

**成果物**: ビルドが通る雛形。

- Cargo workspace（`sim-math`, `sim-data`, `sim-terrain`, `sim-core`, `sim-wasm`, `sim-headless`）
- 固定小数点型 `Fx`, `Vec2Fx`, `Brad` と基本演算、`isqrt`、三角関数テーブル
- 決定論的 PRNG（`SplitMix64` ベースのストリーム導出）
- `wasm-pack` で wasm をビルドし、Vite の開発サーバで読み込める
- CI（fmt / clippy / test / wasm build / 浮動小数点の混入チェック）

**受け入れ条件**
- `cargo test --workspace` が通る
- `wasm-pack build` が成功し、ブラウザで `World::new()` と `tick()` が呼べる
- 浮動小数点チェックが CI で機能している

---

## M1 — 地形

**成果物**: 5 km 四方の地形が生成され、クォータービューで見える。

- 生成パイプライン全 14 段階（03 章）
- グリッド（`height`, `surface`, `water`, `passability`, `cliff`）
- WebGL2 のタイルマップ描画、チャンク焼き
- 手続き生成のタイルアトラス（Wang tile 遷移込み）
- 崖・斜面の側面クアッド
- カメラ（パン・対数ズーム）で 5 km 〜 10 m を行き来できる
- ミニマップ

**受け入れ条件**
- 同じシードで常に同じ地形（ハッシュ一致）
- 河川が海または地図外に到達している（内陸で消えない）
- 通行可能領域が大きく分断されていない
- `Normal` 品質で生成 1.5 秒以下
- 5 km 〜 10 m の全ズーム域で 60 fps

---

## M2 — 個体と移動

**成果物**: 5,000 人が陣形を組んで歩き、押し合う。

- `Soldiers` の SoA レイアウト
- 空間ハッシュ（カウントソート、可変オフセット）
- 移動積分（地形の速度・疲労修正込み）
- 衝突解決（分離と押し合い、質量重み）
- 陣形定義とスロット割り当て
- Unit 単位の経路探索（粗い A* + 局所フローフィールド）
- 兵士スプライトの静的アセット読み込みとインスタンシング描画
  （アセット欠落時は手続き生成のプレースホルダにフォールバック。08 章 4.2 節）
- 描画 LOD L0〜L4 の切り替えとクロスフェード
- 補間（20 Hz → 60 fps）

**受け入れ条件**
- 5,000 体で 60 fps、`ms_per_tick` < 3 ms
- 陣形が地形を通っても崩れすぎず、通過後に再編される
- 密集させても兵士がめり込まない
- 決定論テストが通る（10,000 tick でハッシュ一致）
- **ズームインして 1 人の兵士を追える**

---

## M3 — 編成と指揮

**成果物**: N 階層の指揮ツリーが動き、命令が遅延して伝わる。

- `CommandNode` ツリーと汎用 N 階層エンジン
- 中世プリセットのファクションデータ
- `Order` / `Intent` の定義と伝達（伝令エンティティ、旗信号、音響信号）
- 指揮の継承（指揮官が倒れたときの繰り上がり）
- 陣形変更（所要時間と脆弱性）
- 指揮系統ツリーの UI
- 命令の可視化（矢印、伝令の移動）

**受け入れ条件**
- 総大将の命令が末端に届くまでの時間が距離に比例している
- 伝令が殺されると命令が届かない
- 指揮官が死ぬと継承が起き、その間ノードが `Leaderless` になる
- 命令の遵守・部分遵守・無視がログに出る

---

## M4 — 戦闘と士気

**成果物**: 会戦が成立する。勝敗がつく。

- 白兵戦（エンゲージメント、前列判定、攻撃サイクル、命中・防御・部位ダメージ）
- 武器・防具・ダメージタイプのデータと相性表
- 射撃（弾道、面積命中、装甲貫通の距離減衰、味方誤射、弾薬）
- 疲労
- 個人士気と近傍伝播、`Wavering` / `Broken` / `Rallying`
- 圧迫（crush）
- 追撃フェーズ
- イベントログと統計グラフ

**受け入れ条件**
- 20,000 体で実時間 1x が回る
- **損害の内訳で「追撃」が最大の死因になる**（中世会戦の再現性の指標）
- 士気の崩壊が局所から連鎖的に伝播する（1 人の逃走では何も起きず、
  3〜4 人で雪崩が始まる）
- 同兵力・同品質の対戦で勝率が 50% ± 8% に収まる（`sim-headless` で 200 回）
- 会戦の所要時間が 20 分〜3 時間の範囲に収まる

---

## M5 — 騎兵

**成果物**: 騎兵突撃が会戦の転換点になる。

- 馬エンティティ（体力・疲労・恐怖）
- 突撃（モメンタムの蓄積、接触時の衝撃・ノックバック・貫通）
- 馬の忌避判定（槍衾・杭列・密集陣に対して）
- 落馬と徒歩化
- 突撃後の再編と再突撃
- 追撃と戦場からの離脱

**受け入れ条件**
- 停止した騎兵が歩兵に対して大きな優位を持たない
- 槍衾に正面から突撃すると失敗する（忌避が発生する）
- 崩れた敵・側面への突撃は決定的な効果を持つ
- 追撃に出た騎兵が戻ってくるのに現実的な時間がかかる

---

## M6 — 工兵

**成果物**: 地形が戦闘中に書き換わる。

- 作業システム（タスク、工数、中断と再開）
- 野戦築城（杭・堀・鹿砦・土塁・パヴィス・馬防柵）
- 弓兵の自己築城（杭打ち）
- 地形改修（架橋・渡渉点整備・伐採）と描画への反映
- 攻城兵器（設置・牽引・射撃・要員）
- 兵站（矢の補給、負傷者回収、修理）
- 会戦前の準備フェーズ
- 工兵タスクの UI

**受け入れ条件**
- 杭列が騎兵突撃を実際に止める
- 仮橋のスループットがボトルネックとして機能する（渡河に現実的な時間がかかる）
- 矢の補給が切れると射撃戦が止まる
- 準備時間の長短が防御側の勝率に有意に効く

---

## M7 — 指揮官 AI

**成果物**: 指揮官が性格に従って判断し、それが説明できる。

- `Blackboard`（視認・報告・伝聞、時間による信頼度の減衰）
- 戦況評価（`tactical_skill` によるノイズ）
- `Objective` のユーティリティ評価と下位への分解
- 会戦プラン（8 種）と状況に応じた再選択
- 命令の解釈と歪み、遵守判定
- アーキタイプのデータ
- 判断ログの記録と UI 表示

**受け入れ条件**
- **どの指揮官を選んでも「なぜその判断をしたか」がスコア内訳で見られる**
- `tactical_skill` の低い指揮官が戦況を誤認し、それが UI で「認識 vs 実際」として
  見える
- `ambition` の高い騎士が命令を無視して突撃する事例が発生する
- アーキタイプを変えると同じシナリオの結果が有意に変わる

---

## M8 — UI と体験

**成果物**: 観戦とプレイが成立する。

- 憑依（`Blackboard` による視界制限、直属の子への命令）
- 命令 UI 全種（移動・攻撃・突撃・側面・退却・射撃・工兵・条件付き）
- 兵士・指揮官の詳細パネル
- 時間制御と巻き戻し（スナップショット機構）
- リプレイの保存・読み込み・分岐
- 観戦モード（自動カメラ）
- 一兵士追従モード
- 統計グラフと戦闘報告の自動生成
- i18n（日本語 / 英語）、色覚配慮

**受け入れ条件**
- リプレイが完全再現する（`final_hash` 一致）
- 憑依して命令を出し、伝令の遅延を体感できる
- 観戦モードが会戦の見どころを追える
- 一兵士を選んで最初から最後まで追える

---

## M9 — スケールと仕上げ

**成果物**: 50,000 体が快適に動く。

- wasm SIMD128（衝突判定・距離計算）
- wasm threads（`wasm-bindgen-rayon`）による並列化
  - 衝突・移動・AI・知覚を並列に
  - ダメージイベントの ID 順適用で決定論を維持
- `SharedArrayBuffer` によるゼロコピーのスナップショット受け渡し
- 描画の最適化（視錐台カリング、L3/L4 の間引き）
- 地形キャッシュ（IndexedDB）
- 低スペック端末向けの品質プリセット

**受け入れ条件**
- 50,000 体で 4x 早送りが回る
- **単一スレッドと並列で `state_hash` が完全一致する**
- 60 fps を全ズーム域で維持
- 初回ロード 3 MB 以下

## 将来の拡張（第一版のスコープ外）

第一版の設計はこれらを塞がないようにする。

| 拡張 | 必要な変更 |
|---|---|
| **他の時代**（古代ローマ、ナポレオン期） | ファクションデータの追加のみ。N 階層エンジンはそのまま |
| **火器** | `MissileKind` の追加、煙のエフェクト、装填の長時間化 |
| **マルチプレイヤー** | 決定論とリプレイが既にあるので、命令のロックステップ同期を足す |
| **攻城戦** | 城壁・塔・梯子・坑道。地形グリッドに垂直方向の概念が要る |
| **戦役レベル** | 会戦の外側の層。会戦の入出力（兵力・疲労・士気）を引き継ぐ |
| **捕虜と身代金** | `Broken` の兵士に対する捕縛判定。`ruthlessness` が既に効く |
| **シナリオエディタ** | 地形の手動編集と編成の GUI 構築 |

## 優先順位の考え方

**M4 が最大の山**。ここで「会戦が成立する」ことを確認するまで、
その先の機能（騎兵・工兵・高度な AI）に手を出さない。

M4 の受け入れ条件のうち **「損害の内訳で追撃が最大の死因になる」** が
最も重要な指標。これが満たせないなら、士気モデルか追撃フェーズのどこかが
中世会戦の実態から外れている。数値ではなく構造の問題なので、
先に進む前に直す。
