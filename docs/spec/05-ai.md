# 05. AI と思考ルーチン

## 1. 3 層構造

| 層 | 主体 | 頻度 | 決めること | 出力 |
|---|---|---|---|---|
| **戦略層** | 中間・上位 `CommandNode` の指揮官 | 0.2〜1 Hz | 会戦全体の方針、どの部隊をどこに使うか | 下位への `Order` |
| **戦術層** | 葉ノード（Unit）の隊長 | 2〜5 Hz | 陣形、進路、交戦するか退くか、いつ突撃するか | Unit の目標位置・陣形・交戦状態 |
| **個体層** | 兵士 1 人 | 0.5〜10 Hz | 今この瞬間に何をするか | 操舵ベクトル、攻撃対象、逃走 |

上位ほど遅く、下位ほど速い。上位の判断は数十秒〜数分の時間スケールで、
個体の判断は数百ミリ秒。

## 2. 思考の LOD

全員が個体として存在するが、**思考の頻度を状況で変える**。

```rust
fn think_interval(s: &Soldiers, i: usize, ctx: &Ctx) -> u32 {
    let base = match s.state[i] {
        State::Engaged | State::Charging          => 2,   // 10 Hz
        State::Broken  | State::Shooting           => 4,   // 5 Hz
        State::Advancing | State::Repositioning    => 4,   // 5 Hz
        State::Marching                            => 10,  // 2 Hz
        State::Idle if ctx.nearest_enemy_m[i] > 100 => 40, // 0.5 Hz
        State::Idle                                 => 20, // 1 Hz
        State::Downed | State::Dead                 => u32::MAX,
        _                                           => 20,
    };
    // 反応の速い兵士は少し早く考える
    let r = 128 + (s.attrs[i].reflex as u32) / 2;
    (base * 192 / r).max(1)
}
```

さらに **think_at をエンティティ ID でずらす**（位相分散）。全員が同じ tick に
思考すると 20 Hz のうち 1 tick だけ負荷が跳ねるので、`think_at` の初期値を
`id % interval` にして平滑化する。

陣形アンカーが出す移動目標も、全兵士が毎 tick そのまま採用するのではなく、
兵士ごとの**受理済み陣形目標**へラッチする。更新周期は `reflex` と `discipline` が
高いほど短く、疲労と低士気で長くなる。初回位相は SoldierId のハッシュで散らすため、
命令が部隊へ届いても全員が同じ tick に発進せず、0.2〜1.1 秒ほどの幅で順次反応する。
工兵タスクの作業地点・補給・負傷者回収は、この遅延を通さず即時更新する。

物理（移動・衝突）は思考頻度に関わらず全員 20 Hz で回す。ただし
**完全静止していて周囲に動くものがない兵士は sleeping リスト**に入れ、
衝突判定から外す（後方の予備部隊が大半を占める場面で効く）。

### 2.1 負荷の見積り

50,000 体、平均思考頻度を状況別に加重すると:

| 状況 | 割合 | 頻度 | 思考/秒 |
|---|---|---|---|
| 交戦中 | 15% | 10 Hz | 75,000 |
| 緊張・移動中 | 35% | 5 Hz | 87,500 |
| 行軍 | 20% | 2 Hz | 20,000 |
| 待機・予備 | 30% | 0.5〜1 Hz | 11,250 |
| **合計** | | | **約 194,000 思考/秒** |

1 思考あたり 2 µs の予算なら 0.39 秒/秒 = 1 コアの 39%。実時間 1x では余裕があり、
2〜4x 早送りまでは単一スレッドで回る。それ以上は M9 のマルチスレッド化が必要。

## 3. 個体層 —— 兵士の思考

### 3.1 ユーティリティ AI

行動木ではなく**ユーティリティ AI**を採用する。理由は、性格パラメータが
「行動の選択確率」に連続的に効く形が自然で、パラメータを増やしても構造が
壊れないため。

```rust
fn think_soldier(s: &Soldiers, i: usize, ctx: &Ctx) -> Action {
    let mut best = (Action::HoldSlot, i32::MIN);
    for action in candidate_actions(s, i, ctx) {
        let score = score_action(s, i, ctx, action);
        if score > best.1 { best = (action, score); }
    }
    best.0
}
```

**候補行動**:

| 行動 | 概要 |
|---|---|
| `HoldSlot` | 陣形スロットを維持する |
| `MoveToSlot` | スロットへ戻る |
| `AdvanceWithLine` | 隊列とともに前進 |
| `AttackTarget(id)` | 目の前の敵を攻撃 |
| `DefendSelf` | 防御姿勢（受け・盾を構える） |
| `Shoot(target_area)` | 射撃 |
| `StepBack` | 一歩下がる（前列の交代） |
| `Flee(dir)` | 逃走 |
| `RallyToBanner` | 旗へ戻る |
| `HelpComrade(id)` | 近くの味方を助ける |
| `Loot` | 略奪（会戦の決着後） |
| `Work(task)` | 工兵作業 |

#### 実装（`soldier_ai::IndividualAction`、B2）

任務（`Intent`）が最終目的で、行動はその達成手段。いま実装されているのは 8 つ。

| 行動 | 効果 | 選ばれる条件 |
|---|---|---|
| `FollowOrder` | 部隊の陣形・命令のまま | いつでも |
| `JoinFight` | 相手の位置へ出る | 反応半径内に相手がいる（任務が許す相手） |
| `Support` | 味方が組み合っている相手へ出る | 援護できる戦闘がある |
| `Defend` | その場で受ける | 敵が武器の間合い（1.5 m）まで来た |
| `HoldSlot` | 隊形スロットへ戻る | スロットから 1.5 m 以上離れ、反応半径内に敵がいない |
| `FallBack` | 2 m 退く | 敵が 2.5 m 以内、または局所で数負けしている |
| `Flee` | 15 m 離脱する | 崩れている（`Broken`） |
| `Rally` | 軍旗・指揮官の位置へ | 崩れている／立て直し中で、戻る先がある |

**行き来を防ぐ**。選んだ行動には最低継続時間（0.8 秒＋落ち着きに応じた延長）が
あり、乗り換えには現在行動への継続加点を超える差が要る。ただし次の 2 つは
思考周期も継続時間も待たずに割り込む:

- **自衛**: 至近（3 m）に敵が来たのに、迎撃・援護・受け・後退のいずれでもない。
- **恐慌**: 崩れたのに、離脱でも再集結でもない。

**乱数は 1 回の判断につき 2 回だけ**引く（点数のノイズと継続時間）。候補の数で
引く回数が変わらないので、過去の候補数が結果を左右しない。同点は列挙順で決める。

### 3.2 評価関数

各行動のスコアは、**状況の要素 × 性格の重み**の線形和。

```
score(Flee) =
      threat_local       × w(self_preservation) × 3
    + (1000 - morale)    × 4
    + fatigue            × w(1 - endurance) × 2
    + rear_threat        × 5                    // 背後に敵がいる
    + nearby_broken      × w(1 - composure) × 3 // 周りが逃げている
    - discipline         × 3
    - commander_near     × 2
    - banner_near        × 2
    - bravery            × 3
    - (frontline_ahead ? 400 : 0)               // 前に味方の列がある

score(AttackTarget) =
      target_exposed     × w(aggression) × 3    // 側面・背面を取れている
    + target_wounded     × 2
    + (target_is_noble ? w(ambition) × 4 : 0)   // 騎士は名のある敵を狙う
    + morale             × 2
    - fatigue            × 2
    - (out_of_slot ? w(discipline) × 3 : 0)     // 隊列を離れることの抵抗
```

`w(x)` は `attrs` の 0..255 を係数に写す関数。係数はすべて
`data/ai_weights.toml` に出し、コード変更なしで調整できる。

現在の実装（`soldier_ai::score_actions`）はこの形の整数版で、脅威（方向で
重み付け）・相手の選び具合・距離・士気・疲労・規律・勇敢さ・攻撃性・自己保存・
仲間意識（loyalty）を入力に取る。係数はまだコード内の名前付き定数で、TOML への
移動は TODO P0-1。

**選択にはノイズを乗せる**。決定論を保つため、乱数は
`Rng::stream(seed, soldier_id, Purpose::DecisionNoise, tick)` から引く。
ノイズ幅は `composure` に反比例（動揺している兵士ほど不規則）。

### 3.3 知覚

兵士が読める情報は限られる。

```rust
pub struct Perception {
    pub neighbors: [SoldierId; 12],   // 空間ハッシュから引いた近傍（味方・敵混在）
    pub neighbor_count: u8,
    pub nearest_enemy: Option<(SoldierId, Fx)>,
    pub threat_front: u16,            // 前方 ±60° の敵の重み付き密度
    pub threat_flank: u16,
    pub threat_rear: u16,             // 背後の敵。士気に最も効く
    pub friendly_density: u16,
    pub local_broken: u8,             // 近傍で敗走中の味方の数
    pub commander_dist: Fx,
    pub banner_dist: Fx,
    pub local_crowding: u16,          // 圧迫の元
    pub incoming_missiles: u8,
}
```

近傍は**空間ハッシュの 3×3 セル（6 m 四方）から最大 12 人**をサンプルする。
全員を見るのではなく、決定論的なサンプリング（セル内の先頭から順）で上限を切る。
これが O(n) を保つ鍵。

#### 実装（`sim-core::perception`）

`PerceptionSystem` が兵士ごとに `LocalAwareness` を持つ。更新は兵士ごとに位相を
ずらした周期（既定 8 tick、交戦中は 2 tick）で行い、1 回の走査人数にも上限
（既定 32 人）を置く。全兵士対全兵士の走査はしない。

| 持つもの | 使い道 |
|---|---|
| 視界内の敵・味方の人数 | 局所の人数差、孤立の判断 |
| 正面 / 側面 / 背面の敵の人数 | 反応の速さと士気（下記） |
| 密集（1.5 m 以内の味方） | 押し合いの元 |
| 崩れている味方の人数 | 士気の伝染（B2 以降） |
| もっとも近い敵 | 自衛の判断 |
| **援護できる戦闘**（味方が組み合っている相手） | 「近くに敵がいる」とは別の事実として持つ |

**方向で反応が変わる**。正面の敵にはすぐ反応するが、側面（±60〜120 度）は
0.3 秒、背面はさらに 0.6 秒ほど気づくのが遅れる（反射が速い兵士ほど短い）。
背後に敵が現れたことに気づいた瞬間は、驚きとして士気が落ちる（交戦中の兵士は
警戒しているので驚かない）。

**個人行動の候補は絞る**。攻撃・突撃・側面・包囲・追撃・人物追跡といった
「敵へ出ていく任務」でなければ、隊列を離れてよいのは次のいずれかだけ:

- 援護できる味方の戦闘がある。
- 自衛が要る近さ（3 m）まで敵が来ている。
- 守備任務で、持ち場へ侵入した敵か、近づいてくる敵がいる。

守備任務では、**持ち場から離れていく敵を追わない**。追撃の限界は迎撃半径で、
判定は個人のスロットではなく持ち場の中心から測る。

#### 人物追跡の記憶

人物追跡（`HuntPerson`）は対象の現在位置を常には知らない。追跡隊の誰かが
40 m 以内にいる間だけ最後の目撃位置を更新し、見失えばそこへ向かって探す
（`HuntMemory`: 対象・最後に見た位置・その tick・状態）。

| 打ち切り | 条件 | その後 |
|---|---|---|
| `TargetDown` | 対象が倒れた | 追跡前の任務へ戻る |
| `Lost` | 20 秒見失った、または目撃地点を 5 秒探して見つからない | 同上。前の任務が無ければ現在地の確保（`Hold`） |

打ち切りは `CommandEvent`（`ObjectiveComplete` / `ObjectiveAbandoned`）として
残るので、UI と回帰指標から「なぜ止めたか」を読める。目的の無いまま兵士が
立ち尽くすことはない。

視界そのものは兵士レベルでは厳密に扱わない（列の中では前しか見えない、を
「前列かどうか」で近似）。厳密な視線判定は射撃と指揮官の観測でのみ行う。

### 3.4 出力

思考の結果は**操舵ベクトル**と**行動フラグ**。実際の移動は物理システムが行う。

```rust
pub struct Steering {
    pub desired: Vec2Fx,      // 行きたい方向 × 望む速度
    pub face: Option<Brad>,   // 向きたい方向（移動方向と別でよい: 後退しつつ敵を向く）
    pub effort: u8,           // どれだけ力を入れるか（疲労消費に効く）
}
```

最終的な操舵は複数の要素の重み付き合成:

```
steering = w1 · seek(slot_or_goal)
         + w2 · separation(neighbors)      // 押し合いの前段。重なりを避ける
         + w3 · terrain_avoid(impassable)
         + w4 · threat_response(threat_dir)
         + w5 · cohesion(unit_centroid)    // 隊列から離れすぎない
```

`w2`（分離）は密集陣形では小さく、散兵では大きい。`w5` は `discipline` に比例。

## 4. 戦術層 —— 隊長（Unit）の思考

葉ノードの指揮官が 2〜5 Hz で判断する。

### 4.1 決めること

1. **陣形の維持・変更**
   - 騎兵が接近している → `Schiltron` / `PikeSquare` へ変更するか？
     変更時間 vs 到達までの時間を見積もり、間に合わなければ変更しない
     （中途半端な変更中に突かれるのが最悪）
   - 敵と接触した → `Line` を保つ、崩れたら再編を試みる
   - 森に入る → `Skirmish` に緩める

2. **進路**
   - 目標位置までの経路をフローフィールドまたは A* で計算
   - Unit は「ひとつの塊」として経路を持ち、兵士はスロット位置に従う
   - 経路は 2 段階: 粗い A*（8 m グリッド）→ 局所フローフィールド（2 m）

3. **交戦判断**
   - 目の前の敵と戦うか、下がるか、迂回するか
   - `Hold` 命令なら追撃しない。ただし `aggression` が高く、敵が崩れていれば
     `allow_pursuit` に関わらず追いたくなる（規律との綱引き）

4. **突撃の発動**
   - 騎兵の場合、突撃開始距離の判断が決定的。早すぎれば馬が疲れて衝撃を失い、
     遅すぎれば加速しきれない
   - 最適は 150〜250 m 手前から加速し、接触時に最高速
   - 目標が槍衾を構えていれば `horse_refusal` を見越して回避を検討する

5. **射撃の管理**
   - 射程内か、矢は残っているか、味方が射線にいないか
   - 斉射（volley）か自由射撃か
   - 弾薬が尽きかけたら射撃を止めて温存するか

### 4.2 経路探索の実装

50,000 体に個別の A* は回せないので、**Unit 単位**で経路を持つ。

- **粗いレイヤ**: 8 m グリッドの A*。地形の `passability` と勾配をコストに。
  Unit あたり 1 回、目標が変わったときのみ。数百 Unit × 数秒に 1 回なので安い。
- **局所レイヤ**: Unit の周囲 64 m のフローフィールド（2 m 解像度、32×32）を
  粗い経路の次ウェイポイントに向けて生成。Unit の兵士はこれをサンプルする。
- **回避**: 味方 Unit 同士のすり抜けは避ける。Unit の占有矩形を粗いグリッドに
  書き込み、他 Unit の経路コストに加算する（動的障害物）。

## 5. 戦略層 —— 指揮官の思考

### 5.1 Blackboard（fog of war）

指揮官は**自分が知っていることだけ**で判断する。

```rust
pub struct Blackboard {
    pub own_forces: Vec<KnownForce>,    // 自軍の状況（報告で更新）
    pub enemy_forces: Vec<KnownForce>,  // 敵の推定
    pub terrain_notes: Vec<TerrainNote>, // 気づいた地形（高地・渡渉点・森）
    pub last_updated: u32,
}

pub struct KnownForce {
    pub node: NodeId,
    pub est_pos: Vec2Fx,
    pub est_strength: u32,
    pub est_troop_type: TroopTypeId,
    pub est_morale: u16,
    pub confidence: u16,      // 0..1000。古い情報ほど低い
    pub observed_tick: u32,
}
```

**更新経路**:

| 経路 | 精度 | 遅延 |
|---|---|---|
| 直接視認 | 高（距離と視界条件で劣化） | なし |
| 下位からの報告 | 中 | 伝令の往復時間 |
| 隣接ノードからの伝聞 | 低 | 伝令 2 段分 |
| 偵察部隊（軽騎兵）の報告 | 高 | 伝令時間 |

情報は**時間で腐る**。`confidence` は経過時間で減衰し、一定を下回ると
指揮官は「そこにいるはず」という古い前提で動く。これが誤判断の源になり、
偵察の価値を生む。

**視認の実装**: 指揮官の位置から、敵 Unit の重心への視線を地形の `cover` と
高度で判定する。指揮官が高地にいれば見通しがよく、`confidence` が高い。
森の裏や谷は見えない。全 Unit ペアではなく、指揮官（数百）× 敵 Unit（数百）で
数万回。0.2〜1 Hz なら安い。

### 5.2 戦況評価

```rust
pub struct SituationAssessment {
    pub force_ratio: i16,          // 自軍 / 敵軍（自分が知る限り）
    pub momentum: i16,             // 押しているか押されているか
    pub flank_threats: [u16; 2],   // 左右の側面が脅かされているか
    pub rear_threat: u16,
    pub reserve_available: u32,
    pub terrain_advantage: i16,    // 高地を取っているか
    pub critical_points: Vec<CriticalPoint>,  // 橋・高地・崩れかけの味方
    pub time_pressure: i16,        // 疲労・日没・弾薬の残り
}
```

### 5.3 目的の選択

指揮官は評価から `Objective` を選ぶ。ここでも**ユーティリティ AI**。

```
score(Envelop) =
      (force_ratio > 0 ? force_ratio × 3 : 0)
    + enemy_flank_exposed × 4
    + reserve_available   × 2
    + w(boldness)         × 3
    + w(tactical_skill)   × 2      // 包囲は難しい。下手な指揮官は選ばない
    - enemy_cavalry_uncommitted × 3 // 敵騎兵が残っていると側面が危ない
    - w(caution)          × 3

score(HoldHighGround) =
      terrain_advantage   × 5
    + w(caution)          × 4
    + (force_ratio < 0 ? -force_ratio × 3 : 0)
    + enemy_must_attack   × 4      // 敵が攻めざるを得ない状況なら待つのが最善
    - w(aggression)       × 2
    - time_pressure       × 2

score(CommitReserve) =
      front_line_crisis   × 5
    + enemy_reserve_spent × 3
    + w(boldness)         × 2
    + (momentum > 0 ? momentum × 3 : 0)   // 勝ちに行く投入
    - w(caution)          × 3
```

選ばれた `Objective` は下位ノードへの `Order` に分解される。分解のロジックは
`Objective` ごとに定義（例: `Envelop` → 中央の子に `Hold`、側面の子に `Flank`、
騎兵の子に `Charge` を敵の側面へ）。

### 5.4 指揮官の性格パラメータ

`Attrs`（兵士共通）に加えて:

```rust
pub struct CommanderAttrs {
    pub boldness: u8,        // 大胆さ。攻勢的な選択肢のスコアを押し上げる
    pub caution: u8,         // 慎重さ。守勢・待機のスコアを押し上げる
    pub initiative: u8,      // 独断専行。上位命令からの逸脱しやすさ
    pub obedience: u8,       // 命令遵守。initiative の反対に効く
    pub tactical_skill: u8,  // 戦況評価の精度。低いと assessment にノイズが乗る
    pub ambition: u8,        // 名誉欲。突撃衝動・名のある敵への執着
    pub charisma: u8,        // 指揮下の士気ボーナスと再結集成功率
    pub flexibility: u8,     // 計画変更の速さ。低いと固執する
    pub patience: u8,        // 待てるか。低いと予備を早く使い切る
    pub ruthlessness: u8,    // 味方の損害を許容するか。追撃の徹底度
}
```

**`tactical_skill` はノイズとして効く**のが重要。低い指揮官が「間違った選択肢を
選ぶ」のではなく、「状況を誤認する」ようにする。

```rust
let noise_scale = (255 - attrs.tactical_skill) as i32;
assessment.force_ratio += rng.range(-noise_scale, noise_scale) / 8;
assessment.momentum    += rng.range(-noise_scale, noise_scale) / 6;
```

これにより「自軍が優勢だと誤認して無謀な突撃を命じる」が自然に起きる。

### 5.6 意図を小任務へ分解する（B6）

指揮官の目的（`Objective`）は、子部隊へ同じ命令を配るのではなく、役目へ分けて
割り当てる。

1. **予備**（自軍の 15 %、最低 1 部隊）を司令部の近くに残す。
2. **要点の保持**。`Blackboard::terrain_notes`（高所・渡河点・道）にもっとも
   近い部隊が `GuardArea` で押さえる。
3. **側面警戒**。主戦闘の外側の端にいる部隊が `Screen` に就く（4 部隊以上のとき）。
4. **主戦闘**。残りが正面（`Attack`）・側面（`Flank`）・騎兵の突撃（`Charge`）。
   送る量は敵の戦力の 1.5 倍を目安にし、届いたらそれ以上は送らない。数で劣って
   必要戦力に届かないときだけ、予備を切り崩す。

**任務変更にはコストがある**。同じ役目に就いている部隊は、20 秒経つか任務が失敗
するまで出し直さない。戦況が動くたびに全部隊が同時に向きを変えることはない。

要点は司令部の周囲 300 m を 40 m 間隔で標本抽出して拾う（全セルは走査しない）。

## 6. 会戦プラン（Army レベル）

軍の総大将は開始時に**会戦プラン**を選ぶ。これが全体の初期方針になる。

| プラン | 内容 | 選ばれる条件 |
|---|---|---|
| `CenterPush` 中央突破 | 主力を中央に集中し押し切る | 兵力優位、歩兵の質が高い |
| `DoubleEnvelopment` 両翼包囲 | 中央で拘束し両翼で包む | 兵力優位、騎兵が多い、指揮官の skill が高い |
| `RefusedFlank` 斜行陣 | 片翼を後退させ、強い方の翼で決着 | 兵力劣勢、地形で片翼を守れる |
| `DefendHighGround` 高地防御 | 高地に布陣し、敵の攻撃を待つ | 弓兵が多い、兵力劣勢、防御的な性格 |
| `FeignedRetreat` 偽装退却 | 一部が退いて敵を誘い出し、騎兵で側面を突く | skill と discipline が高い、`cunning` 系 |
| `EchelonAttack` 段階攻撃 | 部隊を時間差で投入し、敵の予備を吸い出す | 部隊数が多い、patience が高い |
| `CavalryReserve` 騎兵温存 | 歩兵で拘束し、決定的瞬間に騎兵を投入 | 重騎兵が多い、patience が高い |
| `Delay` 遅滞 | 交戦を避けて時間を稼ぐ | 大幅劣勢、増援を期待 |

プランは固定ではない。戦況が大きく変われば `flexibility` に応じて再選択する
（頑固な指揮官は最初のプランに固執する）。

## 8. 挙動の観測と回帰シナリオ

判断を作り変えるときに「良くなったか」を数値で言えるようにする。観測は
`sim-core::metrics`、固定 seed の状況は `sim-core::regression` にある。

### 7.3 任務の段階（`MissionState`、B5）

部隊の任務は「受けた」で終わりではなく、段階を持つ。

| 段階 | 意味 |
|---|---|
| `Idle` | 任務を受けていない |
| `Moving` | 目標へ移動している |
| `Deploying` | 着いて隊形・区域へ展開している |
| `Engaged` | 交戦している |
| `Secured` | 達成した（地点を確保した、対象を倒した） |
| `Failed` | 達成できないと判断した |
| `Returning` | 持ち場・元の任務へ戻っている |

- **地点占拠**は中心点への殺到では判定しない。範囲内の味方が 6 割以上で 5 秒
  保てば確保済み、敵が範囲に入れば交戦中へ戻る。区域に入りきらない人数
  （1 人あたり 4 m² で見積もる）は、半径の 1.15 倍の輪に立って周縁を警戒する。
- **地点防衛**は中心・半径・追撃限界に加えて、もっとも近い敵部隊の方角へ正面を
  向ける。
- 段階の変化は `CommandEvent`（`MissionStateChanged`）として残る。条件付き命令
  （敵接近時・損耗率・地点喪失時）は、この段階と `MissionProgress`（滞在開始
  tick、範囲内の味方・敵の人数）を引き金として後から接続できる。

### 7.4 小集団（`squads`、B3）

兵士は「部隊 500 人」ではなく「隣にいる数人」を見て動く。Unit の中に隊形スロット
順で最大 6 人の小集団を作り、近い仲間と局所的な先導役（規律・勇敢さ・忠誠から
決まる）を持たせる。

- **所属は簡単には変わらない**。見直しは 2 秒周期で、3 人を切った集団だけが
  近く（12 m 以内）の集団へ合流する。一人の死で部隊全体が組み替わらない。
- **個人の判断につながる**。仲間が既に出ていれば続きやすく（1 人あたり +90、
  先導役なら +180）、誰も出ていない集団では最初の一人になるのをためらう
  （−120）。集団の重心から離れているほど単独行動を避ける。
- **1 人の敵へ取りつける人数**は 4 人まで。上限に達した敵は候補から外れ、余った
  兵は隣の敵・援護・持ち場へ回る。

### 8.1 観測（`metrics`）

`BattlefieldObserver` は `&World` だけを受け取り、シミュレーションを変更しない。
観測を挟んでも同一 seed の状態ハッシュは変わらない（テストが検査する）。
集計はすべて整数（mm・tick・permille）で、同じ入力なら毎回同じ値になる。

| 指標 | 何を見るか |
|---|---|
| 任務別の行動人数 | 任務ごとに、命令追従・局所迎撃・交戦・待機が何人か |
| 知覚（B1） | 敵が見えている人数、側面・背面から脅威を受けている人数、援護できる戦闘が見えている人数と実際に出ている人数 |
| 人物追跡の段階 | 追跡中・捜索中・打ち切り・対象撃破のノード数 |
| 小集団（B3） | 集団数、平均人数、交戦中の集団数、1 tick に迎撃へ移った最大人数 |
| 任務の段階（B5） | 移動中・展開中・交戦中・確保済み・失敗・帰還中のノード数 |
| 隊列の綱引き（B4） | 進行方向と逆へ押し戻された延べ回数（操舵と衝突解決の衝突） |
| 移動開始 tick の分布 | 命令への反応が何 tick に散るか（ヒストグラムと 1 tick の最大人数） |
| 同方向へ同時に動き出した割合 | 同じ tick・同じ方位へ動き出した人数の比（permille） |
| 戦闘近傍の非交戦人数 | 交戦中の兵士の近くにいながら、参加も援護もしていない人数 |
| 隊形スロットからの距離 | 平均・p90・最大（mm） |
| 標的集中 | 1 人の敵へ向かっている最大人数と、上限を超えた敵の数 |
| 地点占拠率 | `OccupyArea` の範囲内にいる割合（permille） |
| 防衛範囲からの離脱 | `GuardArea` の守備範囲・迎撃範囲の外に出た人数 |

閾値は `MetricsConfig` の名前付きフィールドに集約する（「戦闘のそば」の距離、
「動き出した」とみなす速さ、移動開始と数えるまでの静止時間など）。コードへ
数値を散らさない。

### 8.2 回帰シナリオ（`regression`）

後続の改善を毎回同じ状況で比べるための 5 つの固定 seed シナリオ。

| ID | 状況 |
|---|---|
| `reserve_passes_melee` | 正面衝突中の横を予備隊が通過する |
| `column_front_losses` | 縦隊の前列に損耗が生じ、後列が穴を埋める |
| `defile_then_reform` | 狭路を通過してから開けた場所で再整列する |
| `guard_area_feint` | 防衛地点へ敵が接近し、一部が陽動で脇を通過する |
| `hunt_person_lost` | 人物を追跡中に対象が倒れる |

台本（決められた tick に前列を倒す、追跡対象を倒す）以外の外乱を入れないので、
同じ seed なら指標も状態ハッシュも毎回一致する。

```bash
cargo run --release -p sim-headless -- regress            # 全シナリオ
cargo run --release -p sim-headless -- regress --list     # 一覧
cargo run --release -p sim-headless -- regress --scenario guard_area_feint
```

出力は指標と `state_hash` / `trace_hash`（全 tick のハッシュを畳んだ値）を含む
JSON で、標準エラーには人が読む要約と 1 tick あたりの実測時間が出る。

### 8.3 UI のデバッグ表示

兵士を選ぶと、詳細パネルに任務・現在行動・迎撃対象・目標地点・隊形スロットと
そこまでの距離・反応半径・次の判断までの tick・命令反応待ちの tick・行動継続
の残り tick・局所知覚（見えている敵味方、正面／側面／背面の脅威、最寄りの敵、
援護できる戦闘、密集、崩れた味方）・行動候補（点数、距離、相手が交戦中か、
既に向かっている味方の数）が出る。候補の記録は選択した 1 人だけを対象にし、
判断そのものは変えない。
