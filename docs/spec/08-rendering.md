# 08. レンダリング

## 1. クォータービューの座標系

2:1 ダイメトリック投影（一般に言うアイソメトリック）。

```
ワールド座標: (x, y) [m]、z = 標高 [m]
タイル 1 枚 = 2 m 四方（地形グリッドのセルと 1:1）

基準（zoom = 1.0、1 m = 16 px 水平）:
  TILE_W = 64 px   （2 m の菱形の幅）
  TILE_H = 32 px   （2 m の菱形の高さ）
  Z_SCALE = 24 px/m （標高 1 m あたりの画面上の持ち上げ）

スクリーン座標:
  sx = ( (x - y) * 16 ) * zoom + cam_x
  sy = ( (x + y) *  8 - z * 24 ) * zoom + cam_y
```

`Z_SCALE = 24 px/m` は「標高 1 m の段差がタイル 0.75 枚ぶんの高さに見える」設定。
起伏が読み取りやすく、かつ極端に見えない値。

### 1.1 深度

アイソメトリックの描画順は `x + y` の昇順。CPU ソートは 50,000 体では
無視できないコストなので、**GPU の深度バッファで解く**。

```glsl
// 頂点シェーダ
float depth = 1.0 - (world_x + world_y + world_z * 0.7) / DEPTH_RANGE;
gl_Position = vec4(ndc_x, ndc_y, depth * 2.0 - 1.0, 1.0);
```

- 深度テストは `LESS`、深度書き込み ON
- 半透明（影・エフェクト）は深度書き込み OFF で後段に別パス
- 同じ `x+y` の物体の順序は不定になるが、視覚的に問題ない

これでソートが消え、**兵士全体を 1 ドローコール**で描ける。

## 2. ズームと LOD

### 2.1 ズーム範囲

視野幅 5,000 m 〜 10 m。**500 倍**のレンジ。

| 視野幅 | zoom | px/m（1920 px 幅想定） | 兵士 1.7 m の画面高 |
|---|---|---|---|
| 5,000 m | 0.024 | 0.38 | 0.65 px |
| 2,000 m | 0.060 | 0.96 | 1.6 px |
| 500 m | 0.24 | 3.8 | 6.5 px |
| 128 m | 0.94 | 15 | 26 px |
| 32 m | 3.75 | 60 | 102 px |
| 10 m | 12.0 | 192 | 326 px |

ズームは**対数スケール**で操作する（ホイール 1 ノッチで ×1.15）。
線形だと広域と近接の操作感が両立しない。

### 2.2 描画 LOD

| LOD | px/m | 視野幅 | 地形 | 兵士 | 追加要素 |
|---|---|---|---|---|---|
| **L0** 至近 | ≥ 48 | ≤ 40 m | 2 m タイル + デカール（草・石・血）+ 接地影 | 16ボーン由来の全身剛体パーツ、髪・手足・騎乗馬 | 個人名ラベル、矢の軌跡、血飛沫 |
| **L1** 戦術 | 12〜48 | 40〜160 m | 2 m タイル + デカール | 胴・頭・腕・脚へ簡略化したアニメーションポリゴン | 部隊枠、隊長のマーカー、旗 |
| **L2** 部隊 | 3〜12 | 160〜640 m | 4 m 集約タイル | 低頂点の人型双角錐、兵科色 + 陣営色 | 部隊枠、陣形の輪郭、命令の矢印 |
| **L3** 会戦 | 0.8〜3 | 640〜2,400 m | 16 m 集約タイル | 三角錐ポリゴン。状態と騎乗を高さ・色で区別 | 前線ライン、部隊アイコン、指揮系統の線 |
| **L4** 戦域 | < 0.8 | > 2,400 m | 事前生成の地形テクスチャ 1 枚 | 決定論的に間引いた三角形ポリゴン | Battle 単位のアイコン、矢印、地名 |

人物スプライトは全LODで使用しない。LODは同じRustエンジンが生成するポリゴンの
部位数と頂点数だけを変える。シミュレーションは常に個体単位（00章 非交渉事項3）。

L3/L4は描画上限を設け、兵士IDに対して決定論的な間引きを行う。

### 2.3 LOD 遷移

LOD境界はカメラの `px/m` だけで決まり、人物のモーション位相と状態はLOD変更後も
同じ内部状態を継続する。将来、形状間の短いクロスフェードを追加できる。

## 3. 地形の描画

### 3.1 チャンク方式

地形タイルは**チャンク単位でオフスクリーンテクスチャに焼く**。

```
チャンク = 64 × 64 タイル = 128 m × 128 m
5 km マップ = 39 × 39 = 1,521 チャンク
```

- 可視チャンクのみ焼く。カメラ移動で必要になったら焼き、LRU で捨てる
- 焼いたテクスチャは 1 枚のクアッドとして描画 → 地形のドローコールは
  可視チャンク数（画面内で最大 20〜40 枚）
- ズームアウト時は**粗い解像度で焼いたチャンク**を使う（ミップ的に 3 段階）

### 3.2 マップチップ

タイルアトラスは**ビルド時に手続き生成**する（`web/tools/genart/`）。

- 各表示タイル × バリエーション 4 種
- **47-blob（Wang tile）遷移セット**: 表示タイルの境界（森と草原、草と泥）を
  自然につなぐ。隣接 8 方向のビットマスクから遷移タイルを選ぶ
- タイル 1 枚 64 × 32 px（菱形）+ 上下のマージン
- アトラス 1 枚 2048 × 2048 px（PNG、生成時に決定論的）

### 3.3 高低差と崖

- タイルの 4 隅の標高から菱形を**変形**する（4 頂点をそれぞれ z 分持ち上げる）。
  これで斜面が斜面に見える
- 隣接タイルの標高差が閾値（0.5 m）以上なら、間に**側面のクアッド**を立てる。
  崖・段差はこれで表現
- 側面のテクスチャは地質に応じたもの（岩肌、土、草の断面）
- 標高に応じた明度調整（`z` が高いほどわずかに明るく）で立体感を出す

### 3.4 水面

- `water` グリッドから水面ポリゴンを生成
- 深さで色を変え、時間で微動するノーマル（シェーダ内、シミュレーションとは無関係）
- 岸のセルは半透明のブレンド

## 4. 兵士の描画

### 4.1 状態保持型Rustエンジン

`sim-render` は人物ごとにモーション位相、直前・現在モーション、切替補間率、
決定論的な体格・配色を保持する。シミュレーションから20 Hzで届く20-byteの
一括スナップショットを位置の正本とし、描画フレームでは位置を積算しない。

```ts
army.applySnapshot(snapshot, stride, tick); // 新tick到着時のみ
army.setCamera(centerX, centerY, pxPerM, width, height, worldSize); // 変更時
army.step(dt, alpha, lod);                   // 描画フレーム
```

`state` とflagsから idle / walk / run / combat / shoot / work / brace / fall / deadを
選び、切替は0.24秒で姿勢パラメータをクロスフェードする。腕を下ろした姿勢を
全モーションの基準にする。騎乗中は同じ骨格を座位へ変換し、馬もポリゴン生成する。

### 4.2 RenderPacket

Rustは画面外個体をポリゴン生成前に除外し、LODに応じた三角形列を次の形式で返す。

```text
[clipX, clipY, clipZ, clipW, r, g, b, a] // 32 byte/vertex
```

TypeScript側は人物・馬・ボーン・モーションを解釈せず、Wasmメモリの配列をVBOへ
転送して `gl.drawArrays(gl.TRIANGLES, ...)` を1回呼ぶ。テクスチャ、UV、人物画像、
スプライトアトラスは存在しない。WebGL2非対応時もCanvas2Dの三角形へ落とし、
画像にはフォールバックしない。

### 4.3 体格と剛体パーツ

身長、体格、頭、腕、脚の比率は、関節間translationを決める時点で反映する。
胸・肩・首・腕・脚の形状は反映後の関節座標から生成し、関節部で少し重ねる。
頭髪は顔の前へ張り出さない頭頂・つむじ・後頭部の3パーツで構成する。

### 4.4 L0 の追加表現

至近距離でのみ描く。

- **接地影**: 楕円の半透明クアッド。地形の傾きに沿わせる
- **武器の軌跡**: 攻撃フレーム中、武器の先端に短い残像
- **血**: ダメージ発生時にパーティクル。地面にデカールとして残る（LRU で消す）
- **足跡・砂塵**: 移動速度に応じて。泥では泥はねが大きい
- **息**: 疲労が高いと荒い息（寒冷の天候で白く見える）

これらは**すべて描画専用**で、シミュレーション状態に一切影響しない。

### 4.5 死体

`Dead` と `Downed` は横倒しの骨格・低頂点形状として描き続ける。
数千体まで表示し、それを超えたら古いものから描画を省略する
（シミュレーション上は残り続ける）。

## 5. エフェクトと矢

- **矢**: `Projectile` の位置から短い線分を描く。L2 以下では省略し、
  代わりに射撃部隊から目標エリアへの**射線の帯**を薄く描く
  （数千本の矢を個別に描いても視認できないため）
- **砂塵**: 騎兵の集団移動で発生。GPU パーティクル
- **煙**: なし（火器がないため）

## 6. UI オーバーレイ（SVG / HTML）

WebGL の上に SVG レイヤを重ねる。数が少なく（数百要素）、
ズームとは独立してスケールする（ラベルは常に読めるサイズ）。

| 要素 | 内容 |
|---|---|
| 部隊枠 | Unit の外接矩形。陣営色。選択中は強調 |
| 陣形の輪郭 | 陣形の理想形と現状のズレを見せる |
| 命令矢印 | 発令中の命令の目標へのベジェ曲線。伝令が移動中なら破線 |
| 指揮系統ツリー | サイドパネル。ノードの状態（`Leaderless` は赤） |
| 前線ライン | 両軍の接触面を推定した曲線 |
| 部隊アイコン | L3/L4 で、部隊の種類と規模を示す記号 |
| 士気バー | 選択中の Unit の上に |
| ツールチップ | ホバーした兵士・部隊の要約 |
| ミニマップ | 地形サムネイル + 部隊の点。Canvas2D で描く |
| 地名ラベル | 生成された地形の特徴（「北の丘」「浅瀬」）に自動命名 |

SVG のノード数が増えると重くなるので、**可視範囲かつ LOD に応じた要素のみ**を
DOM に出す。L0/L1 では部隊枠を出さない（近すぎて邪魔）。

## 7. カメラ

| 操作 | 入力 |
|---|---|
| パン | 右ドラッグ / 中ドラッグ / WASD / 画面端 |
| ズーム | ホイール（対数、カーソル位置を中心に）/ +− |
| 部隊にフォーカス | 部隊をダブルクリック → 適切なズームで中心に |
| 指揮官視点 | 指揮官を選んで F → その指揮官の位置と視界に固定 |
| **一兵士を追う** | 兵士を選んで T → その兵士に追従。L0 固定 |
| 自動観戦 | O → 「交戦密度が高い」「崩壊が始まった」場所を自動で追う |
| 前の視点に戻る | Backspace |

**一兵士を追うモード**は「個々の人の行動が見える」という要求の中心。
追従中は、その兵士の思考ログ（05 章 7 節）をサイドパネルに流し続ける。

カメラ移動には慣性と減衰を入れる。ズームはカーソル位置を固定点にする
（地図アプリと同じ挙動）。

## 8. 描画の性能予算

60 fps = 16.6 ms のうち、描画に使えるのは 10 ms（残りは UI と補間）。

| パス | 予算 | 内容 |
|---|---|---|
| 地形チャンク | 2 ms | 可視 20〜40 クアッド + 未焼成チャンクの焼き（1 フレーム 1 枚まで） |
| 人物ポリゴン生成・転送 | 3 ms | 画面外カリング + LOD頂点上限 + 1ドローコール |
| 建造物・攻城兵器 | 0.5 ms | 数百インスタンス |
| 矢・エフェクト | 1 ms | 数千パーティクル |
| 影・デカール | 1.5 ms | L0/L1 のみ |
| SVG オーバーレイ | 1.5 ms | 数百 DOM 要素の更新 |
| ミニマップ | 0.5 ms | 4 フレームに 1 回だけ更新 |

**ポリゴンVBOの更新**が最大の懸念。L0/L1は画面内人数が上限を超えたら
より簡単なポリゴンへ自動降格し、L3/L4は決定論的に間引く。JavaScriptは
Wasmメモリの `Float32Array` viewをそのまま `bufferData` へ渡す。

## 9. 補間

シミュレーションは 20 Hz、描画は 60 fps。3 フレームに 1 回しか新しい状態が来ない。

```ts
const alpha = (now - snapshotTime) / TICK_MS;   // 0..1
pos = lerp(prev.pos, curr.pos, alpha);
facing = lerpAngle(prev.facing, curr.facing, alpha);
```

- 補間は**レンダラ内で完結**し、シミュレーションに戻さない
- 前スナップショットに存在しない兵士（新規）は補間せず即座に表示
- 倍速時（8x 以上）は補間しない（どうせ動きが速すぎて見えない）
- ワープ（テレポート的な位置変化）を検出したら補間をスキップする閾値を設ける
