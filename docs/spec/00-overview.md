# 00. 概要とスコープ

## 1. これは何か

中世ヨーロッパ（おおよそ 12〜15 世紀）の**会戦**を、参加する人間一人ひとりの単位で
シミュレートし、ブラウザ上で観察できるようにするもの。

決定的に重要なのは「集団を数値で処理する戦術級ウォーゲーム」ではないという点。
2 万人の兵士がいるなら 2 万個の独立した意思決定主体が存在し、それぞれが
自分の視界・自分の疲労・自分の恐怖に基づいて行動する。会戦の勝敗は、
上から与えられた戦力比ではなく、**個々の兵士の士気が崩れて敗走が伝染する過程**から
創発する。

## 2. 何を再現したいのか

中世会戦の実態として、以下は明示的にモデル化する。

- **前列しか戦っていない。** 数百人の部隊がぶつかっても、実際に武器を振るえるのは
  接触面の第1列（せいぜい第2列）だけ。後列は押しているだけで、体力を温存しつつ
  前列と交代する。だから「厚み」は正面戦闘力ではなく**持続力と士気**として効く。
- **死因の大半は敗走後の追撃。** 押し合っている間の死傷率は低い。陣形が崩れて背を
  向けた瞬間から死者が積み上がる。したがって勝敗の分岐点は「どちらが先に折れるか」。
- **疲労が勝敗を決める。** 20〜30kg の装備で数時間戦えば、技量差は疲労差に飲まれる。
- **騎兵は速度が価値。** 停止した騎兵は歩兵に毛が生えた程度。突撃の衝撃力は助走で
  得た運動量に依存し、槍衾の前では馬自身が忌避する。
- **命令は遅れて届き、歪んで伝わる。** 総大将の意図が最前線の隊長に届くには伝令が
  馬で走る時間がかかり、その間に状況は変わっている。名誉欲の強い騎士は命令を無視して
  突出する。
- **地形が全部を決める。** 泥、坂、水域の渡渉点、森の縁。クレシーもアジンクールも
  バノックバーンも、地形と工兵仕事が会戦を決めている。

## 3. スコープ

### 含むもの（第一版）

| 領域 | 範囲 |
|---|---|
| 時代 | 中世ヨーロッパ 12〜15 世紀 |
| 兵種 | 重装歩兵、槍兵、パイク兵、長弓兵、弩兵、重騎兵、軽騎兵、工兵 |
| 武器 | 剣・ロングソード・メイス・戦斧・槍・パイク・ハルバード・ダガー・ランス・長弓・弩・投石紐 |
| 防具 | ギャンベゾン、チェインメイル、コート・オブ・プレート、ブリガンダイン、プレートアーマー、各種ヘルム、各種シールド |
| 地形 | 高低差、森、崖、湖、海、湿地、泥濘、農地、道路、橋 |
| 規模 | 片軍 1,000〜25,000（合計 50,000 が上限目標） |
| 時間 | 会戦 1 回ぶん（sim 時間で 30 分〜4 時間） |
| 空間 | 既定 5km × 5km（2km〜8km で可変） |

### 含まないもの（第一版では作らない）

- 攻城戦（城壁・塔・坑道戦）。攻城兵器そのものは野戦運用の範囲で入れる。
- 戦役（キャンペーン）レベルの移動・補給・政治。会戦単体で完結する。
- 海戦。海は地形として存在するが渡海はしない。
- 火器（ハンドキャノン、初期の砲）。15 世紀後半以降として将来の拡張に回す。
- マルチプレイヤー。ただし決定論とリプレイの設計は将来の対戦化を塞がないようにする。
- 3D。クォータービューの 2.5D で完結する。

## 4. 用語

| 語 | 意味 |
|---|---|
| **Soldier** | 個体の兵士。すべての人間はこれ。指揮官も Soldier である |
| **Unit** | 指揮ツリーの葉。同じ陣形を共有する最小の戦術単位（20〜200 人） |
| **CommandNode** | 指揮ツリーのノード。葉が Unit、中間が部隊群、根が軍 |
| **Echelon** | ノードの階層レベル（0 = 軍、大きいほど下位） |
| **Order** | 上位から下位へ渡される命令。伝令によって遅延して届く |
| **Objective** | ノードが自分で選ぶ「今やろうとしていること」 |
| **Formation** | Unit の陣形。横隊・楔・円陣など |
| **Slot** | 陣形内で各兵士に割り当てられる目標位置 |
| **Tick** | シミュレーションの最小時間刻み。20 Hz = 50 ms |
| **Fx** | 固定小数点数。1 単位 = 1/1024 m |
| **Archetype** | 性格パラメータのプリセット（「名誉に飢えた若騎士」など） |
| **Blackboard** | 指揮官が「知っていること」を保持する構造。fog of war の実体 |

## 5. 設計上の非交渉事項

以下は設計判断の際に常に優先される。破る場合は仕様書を改訂する。

1. **決定論を壊さない。** 浮動小数点はシミュレーション状態に一切入れない。
   イテレーション順序に依存する処理を書かない。乱数はエンティティごとの
   独立ストリームから引く。
2. **描画はシミュレーションを一切変更しない。** レンダラは読み取り専用。
   カメラ位置やズームがシミュレーション結果に影響してはいけない。
3. **個体は常に個体。** ズームアウトしても兵士を「部隊という塊」に置き換えない。
   描画を簡略化するのは自由だが、シミュレーションの対象は常に個人。
4. **すべての行動には理由がある。** どの兵士を選んでも「なぜ今それをしているか」を
   UI に表示できること。ブラックボックスな数値処理を入れない。
5. **数値はデータに出す。** 武器の威力も性格の分布も、コードではなく `data/` の
   TOML に置く。バランス調整に再コンパイルを要求しない。
