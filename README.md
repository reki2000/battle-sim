# battle-sim

中世ヨーロッパの会戦を、**兵士 1 人単位・最大数万人**でブラウザ上でシミュレートする。

地形はシードから自動生成され、司令官・隊長・兵士がそれぞれ独立した思考ルーチンを
持って行動する。会戦の勝敗は上から与えられた戦力比ではなく、**個々の兵士の士気が
崩れて敗走が伝染する過程**から創発する。

- Rust → wasm（シミュレーション）＋ TypeScript（UI・描画）
- 固定小数点による完全決定論。シードと命令ログだけで会戦全体を再現できる
- クォータービュー。5 km 四方から 10 m 四方まで連続してズームできる
- 観戦するだけでなく、任意の指揮官に憑依して命令を出せる（命令は伝令で遅れて届く）

## 現在の状態: M3 コア（編成と指揮）

M0〜M1 の地形基盤に加え、M3 のシミュレーションコアを実装した。実装済みなのは
以下。

**M0 からの引き続き**
- 固定小数点数学（`Fx`、`Vec2Fx`、`Brad`、整数平方根、事前生成の三角関数テーブル）
- 決定論的な PRNG（エンティティ・目的・ティックからストリームを導出）
- 兵士の SoA レイアウト、空間ハッシュ、移動積分、衝突解決（押し合い）
- wasm 境界と描画スナップショット

**M1 で追加**
- 地形生成の全 14 段階: ノイズによるベース標高、熱浸食、優先度フラッドに
  よる湖の確定、D8 流向・流量集積、河川分類、崖検出、水系連動の湿度、
  海岸線、道路（A*）、会戦地の自動評価
- 大域ノイズの粗いグリッド + バイリニア補間によるアップサンプル
  （5 km マップの生成時間を 1/2〜1/3 に短縮）
- WebGL2 の地形レンダラ（チャンク焼きの単純化版。タイルアトラスではなく
  セルごとの直接彩色 + ヒルシェードで、理由は `render/terrain-gl.ts` 冒頭に
  記載）
- ミニマップ
- CLI（ベンチ・決定論検証・地形統計）と CI

**M3 で追加**
- 任意の深さを持つ `CommandNode` ツリーと葉 `Unit`
- `Order` / `Intent`、伝令・旗・角笛による遅延伝達
- 伝令の損失、遵守・部分遵守・無視の決定論的イベントログ
- 指揮官喪失時の `Leaderless` → `Succeeding` → `Commanded` 継承
- 陣形プリセット、スロット再割り当て、所要時間付き陣形変更
- `data/formations.toml` と `data/factions/medieval_western.toml`

**M9 の後に追加**
- 史実の会戦プリセット（`sim-core/src/scenario.rs`）。地形（生成パラメータ +
  シナリオ固有の整形）・両軍の陣容・指揮官の性格をひとまとめに宣言し、
  UI から選んで丸ごと組み替えられる
- 生成後の地形整形（`sim-terrain/src/shaping.rs`）。森の縁・泥濘の帯・緩斜面を
  焼き込む
- [アジンクール 1415](data/scenarios/agincourt_1415.toml) /
  [クレシー 1346](data/scenarios/crecy_1346.toml) /
  [バノックバーン 1314](data/scenarios/bannockburn_1314.toml)
- 兵士どうしの当たり判定を歩容で変える（`sim-core/src/soldiers.rs`）。歩いて
  いれば 20 cm、走っていれば 40 cm の隙間があれば味方の列をすり抜けられ、
  隙間が足りないまま走り込めば転倒する
- 死体を高さ 25 cm の低い障害物として扱う（`sim-core/src/corpses.rs`）。
  跨げるので通行は塞がないが、重なった段数だけ越えるのに時間がかかる
- 徒歩兵の助走突撃（`sim-core/src/charge.rs`）。走った距離がモメンタムになり、
  接触時の衝撃・ノックバック・士気ダメージに変わる。兵士は自分の判断で
  「離れた敵へ走り込む」「噛み合った戦列でいったん下がって助走し直す」を選ぶ
- 移動による疲労（歩行 +3 / 早足 +8 / 全力疾走 +25 per 秒）。走れば疲れるので、
  助走突撃は常に得な行動ではない
- 旋回速度の上限（静止 270°/s 〜 騎乗 90°/s）。瞬時に振り向けないので、
  側面・背面を取られた兵士は向き直る前に討たれる
- 白兵戦の間合い維持（`sim-core/src/lib.rs` の `apply_melee_standoff`）。剣は
  踏み込み、槍・パイクは突ける距離で止まって踏み込まれたら下がる
- 突撃の寸前失速と、受ける側の「盾を構えて受け止める姿勢」。集団で突っ込めば
  止まりにくく、単独で密集した戦列へ突っ込めば足が止まる
- 疲労による前後列の交代（`Unit::soldiers` のスロット交換）。規律の高い部隊だけ
  が疲れた前列を下げられる
- 転倒した兵士は横倒しの姿勢で描かれ、受け止める姿勢は盾のきらめきで見える

**まだ無い**もの: TOML の実行時ローダー、シナリオの準備時間・天候・勝利条件、
崖の側面ジオメトリ（現状は暗い縁取りで代替）。
順序は [ロードマップ](docs/spec/12-roadmap.md) を参照。

## 会戦プリセット

「有名な会戦の地形・陣容・指揮官の性格」をひとまとめに宣言したもの。UI 左上の
プルダウンから選ぶと、ワールドを丸ごと組み直す。`?scenario=agincourt_1415`
（id でも index でも可）を URL に付ければ、起動直後からそのプリセットで始まる。

**命令は一切与えない。** 両軍は陣形の上に立つだけで、動き出すのは各軍の
指揮官 AI（M7）が、与えられた性格と会戦プランから下す判断による。名誉に飢えた
前衛が命令を待たずに突出するのも、シナリオが書いた筋書きではなく
`ambition` と `obedience` の帰結として起きる。

```bash
# 登録されているプリセットを見る
cargo run --release -p sim-headless -- scenario

# ブラウザなしで最後まで回し、両軍の残存と死因内訳を出す
cargo run --release -p sim-headless -- scenario --scenario agincourt_1415
```

### 収録している会戦

3 つとも同じ 14 世紀の西欧だが、効いている仕掛けが違う。

| プリセット | 会戦場 | 決め手になる仕掛け |
|---|---|---|
| アジンクール 1415 | 森に挟まれ、340 m から 210 m へ狭まる泥濘の耕地 | 泥・隘路・杭列・長弓・仏軍の指揮の分裂 |
| クレシー 1346 | 挟むもののない開けた緩斜面（高低差 9 m） | 高低差・長弓と弩の射程差・落とし穴・到着順に突っ込む騎兵 |
| バノックバーン 1314 | 小川に挟まれ、背後ほど狭まる低湿地 | 湿地（騎兵は入れない）・パイクのシルトロン・展開できない大軍 |

兵数はどれもブラウザで回せるよう縮尺してある。会戦場の幅も同じ比で縮めることで、
「敵より広い正面を取れない」という骨格を保っている。

`sim-headless scenario` で 60 分ぶん回した結果（開発機、決定論なので再現する）:

| プリセット | 配置 | 生存 |
|---|---|---|
| アジンクール | 英 1,775 / 仏 2,750 | 英 1,049 / 仏 1,570 |
| クレシー | 英 1,750 / 仏 2,300 | 英 1,666 / 仏 13 |
| バノックバーン | 蘇 1,130 / 英 2,550 | 蘇 216 / 英 0 |

クレシーとバノックバーンは史実と同じ側が勝つ。アジンクールは決着まで行かず、
英軍が少ない損害で持ちこたえたところで時間切れになる。勝利条件（仕様 10 章
`[victory]`）が未実装なので、勝敗は死傷と残存から読む必要がある。

観察できること:

- **アジンクール**: 仏軍騎兵は両翼とも杭列と長弓の前で崩れ、徒歩重装兵は泥の
  中で消耗する。名誉に飢えた前衛が命令を待たずに動く
- **クレシー**: 長弓が弩を射程で圧倒し、騎兵は落とし穴の前で止まる。仏軍の
  損害の多くは矢ではなく**後続に押し込まれた圧迫**による
- **バノックバーン**: グロスター伯の騎兵が単独で突っ込んで槍衾に潰れ、
  湿地に押し込まれたイングランド軍は数を活かせないまま崩れる

このシミュレータで再現できるのは「地形・射撃・築城・指揮の性格」までで、
次のものはまだ実装されていない。

- 装備重量が泥での消耗に効く（仕様 03 章 3.2 節）
- 矢が尽きた長弓兵が槌を持って白兵戦に加わる（武器の持ち替え）
- 天候・準備時間・勝利条件（仕様 10 章の `[time]` / `weather` / `[victory]`）

### 実測値（M1 時点、開発機での参考値）

**シミュレーション**（移動と衝突のみ。AI・戦闘は未実装）

| 兵数 | ms / tick | 実時間 20 Hz に対する余裕 |
|---|---|---|
| 20,000 | 4.7 | 10.6x |
| 50,000 | 11.5 | 4.4x |

**地形生成**（`relief 450`、既定の川密度・道路数）

| マップサイズ | 生成時間 |
|---|---|
| 2,000 m | 0.27 秒 |
| 3,000 m | 0.64 秒 |
| 5,000 m（既定） | 1.9 秒 |

仕様の目標（Normal 品質・5 km・1.5 秒以内）にはわずかに届いていない
（当初の未最適化版は 5.3 秒だった）。2〜3 km では十分に余裕がある。
主なコストは熱浸食と優先度フラッドで、さらに縮めるなら並列化や
ハイドロロジー計算自体の高速化が必要になる。

## 人物スプライト生成

人物画像の意味はシミュレーター側の `data/visual-profiles/*.toml` を正本とする。
プロファイルが時代・地域、必要な兵科ロールと説明、行動、状態から行動への対応を
定義し、画像生成側がロールや行動を独自に追加することはない。既定プロファイルは
14世紀ヨーロッパで、画風の既定値はフルカラーフォトリアル。

`.agents/skills/generate-battle-sprites/` はプロファイルを読み込み、服装・防具・武器など
画像に必要な情報をWeb上の史料から収集してから、ImageGen用の正面・背面基準画像、
各方向・各行動のフレーム、スプライトシート、実行時manifestを生成・検証する。
画像セルは200×300 px、シートは8方向（列）×8スロット（行）の1600×2400 pxとする。

- 通常行動: `0`〜`7` を等時間で再生し、各位相の選択時間を均等にする
- `idle`: 2フレーム×4待機スタイル。兵士ごとに1スタイルを固定選択する
- `dead`: アニメーションしない静止姿勢を8種類用意し、兵士ごとに固定選択する

責務境界とデータ形式は
[レンダリング仕様](docs/spec/08-rendering.md#42-スプライトアセットと-imagegen) と
[データ形式仕様](docs/spec/10-data-formats.md#41-人物画像の責務境界) を参照。

## セットアップ

```bash
# 前提: Rust 1.75+, Node 22+
rustup target add wasm32-unknown-unknown
cargo install wasm-pack --locked
```

## ビルドと実行

```bash
# 1. ネイティブのテスト（ブラウザなしで全ロジックを検証できる）
cargo test --workspace

# 2. wasm をビルドして web/src/wasm/ に出す
wasm-pack build crates/sim-wasm --target web \
  --out-dir ../../web/src/wasm --out-name sim

# 3. 開発サーバ
cd web && npm install && npm run dev
```

`web/package.json` の `npm run wasm` は手順 2 のショートカット。

## CLI

`sim-headless` はブラウザなしでシミュレーションを回す。バランス調整・性能計測・
決定論の回帰テストはこれで行う。

```bash
# 性能を測る
cargo run --release -p sim-headless -- bench --soldiers 20000 --ticks 500

# 同じシードで結果が一致するか検証する
cargo run --release -p sim-headless -- verify --soldiers 5000 --ticks 5000

# 地形の統計を見る（水系・崖・道路・会戦地候補も出る）
cargo run --release -p sim-headless -- terrain --size 2000 --relief 450 \
  --river-density 500 --roads 2 --sea north

# 史実の会戦プリセットを最後まで回す
cargo run --release -p sim-headless -- scenario --scenario agincourt_1415
```

## 開発上の規約

仕様書の [非交渉事項](docs/spec/00-overview.md#5-設計上の非交渉事項) がすべてに優先する。
特に次の 2 つは CI が機械的に検査する。

1. **`sim-math` / `sim-core` / `sim-terrain` に浮動小数点を書かない。**
   決定論はプラットフォームに依らない整数演算だけで保たれる。
   例外は `sim-core/src/snapshot.rs`（描画用の変換）のみ。
   `tools/check_no_float.sh` が検査する。

2. **同じシードからは常に同じ結果が出る。**
   `sim-headless verify` が全ティックの状態ハッシュを突き合わせる。

その他:

- `HashMap` をシミュレーション状態の走査に使わない（イテレーション順が不定）。
- 乱数は必ず `Rng::stream(seed, entity, purpose, tick)` から引く。
  グローバルな RNG 状態を持たない。
- 各システムは「前フェーズの確定値を読み、自分の出力配列に書く」。
  同一フェーズ内で他エンティティの更新後の値を読まない（並列化の前提）。
- 描画はシミュレーションを一切変更しない。レンダラは読み取り専用。
